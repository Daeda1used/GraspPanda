    Model zoo¶

    One method has been trained and evaluated here: GSNet, trained from scratch with the recipe of its config and scored on the whole test splits of GraspNet-1Billion and GraspClutter6D, provenance reproduced (see Trained and evaluated here). Its weights are not published yet, so the zoo cannot download them. It does not meet the admission rule below: it is above the paper by more than 1 AP on every split; the gap and what is known about it are stated with its numbers. Every other measured number is how the weights released by the authors score in this toolbox: see Authors' checkpoints scored by this toolbox and GraspClutter6D transfers. Those numbers have the provenance author-ckpt; they are not reproductions.

    Admission gate¶

    A method enters only with all of: config, weights with sha256, training log, a result record produced by the pinned evaluator, and the run snapshot.

    Every number carries its provenance and they are never mixed in one column:

    Provenance Meaning
    reported Taken from the paper or the authors' repository.
    author-ckpt The authors' released weights, evaluated in this toolbox.
    reproduced Trained and evaluated in this toolbox.

    Gate: |reproduced − reported| ≤ 1.0 AP on each of seen / similar / novel. If the gate fails the entry may still be published, with the gap, the author-ckpt number and the diagnosed cause stated. Results with and without collision filtering are always separate rows.

    A measured number is shown only when a result record backs it. The record of every author-ckpt and reproduced row is committed under configs/<method>/records/ and named by the row of configs/<method>/metafile.yaml; it holds the per-scene values, the coverage, the post-processing chain, the inputs derived from ground truth, the config hash, the code commit and the sha256 of the weights. A test recomputes every measured number of the tables below from those per-scene values.

    Recording a result¶

    grasppanda test <config> --weights <checkpoint> --opts runtime.work_dir=<work directory>
python -m tools.record_result <work directory> --method <directory below configs/>

    The second command refuses a run that did not score every frame of the whole test split, that ran on uncommitted code, or whose weights cannot be tied to the file the metafile lists (for a converted checkpoint: the file it was converted from, which the converter notes in the converted file). Otherwise it copies the result records to configs/<method>/records/<model>_<provenance>_<split>_<variant>.json, with the directories of the machine replaced by the name of their environment variable, and prints the rows to paste into the metafile, the numbers computed from the per-scene values. Run again, it changes nothing and says whether the metafile states the rows. The table lines of this page and of the method's README are then written by hand; the tests name the lines that are missing.

    While the metafile has no weights entry for the model, say what the weights are with --provenance author-ckpt or --provenance reproduced; the tool then prints the entry to complete. Weights trained here may be listed before they are published: the entry then has url: null, license: null and a short note saying that they are not published yet, beside their sha256.

    Trained and evaluated here¶

    GraspNet-1Billion, protocol graspnet1b-sv-v1: the whole test split, 90 scenes and 23,040 frames of the RealSense, all scored. AP in percent on seen / similar / novel.

    reproduced is a model trained from scratch by this toolbox with the recipe of its config and scored through grasppanda test: off is the prediction as emitted (variant raw), on the model-free collision filter of the reference (variant cd). The workspace crop is derived from the ground-truth segmentation, as in the reference (gt_assisted: workspace). The training run is described in configs/gsnet/README.md.

    Method Camera Collision filter reproduced reported reproduced − reported
    GSNet RealSense off 68.83 / 60.35 / 25.20 65.70 / 53.75 / 23.98 +3.13 / +6.60 / +1.22
    GSNet RealSense on 71.23 / 62.29 / 26.42 67.12 / 54.81 / 24.31 +4.11 / +7.48 / +2.11
    • Against the admission gate. The gate asks for at most 1.0 AP between reproduced and reported on each split. GSNet is above the paper by more than that on every split, most on similar, and the gap is not explained. What is known: this implementation equals the public reference implementation stage by stage, including every loss term of a recorded training batch, so its training step is the reference's; a model trained independently with the reference code, on a modified graspness label set, also scores above the paper; and the paper's numbers come from the authors' original code, which is not public. No author-ckpt number stands beside it: the file released with the reference code does not reach the paper's numbers in either implementation (configs/gsnet/README.md).
    • One run. One training run with one seed, scored once. A training with the unmodified reference code was not run here, and the spread over seeds was not measured.
    • The weights are not published yet. They were trained on GraspNet-1Billion (CC BY-NC-SA 4.0), and whether and where they are published has not been decided. The metafile lists them with their sha256 and no url, so the zoo, GraspInferencer and grasppanda demo say that they are not published instead of downloading anything; the training log and the run snapshot are not published either.
    • The same model on GraspClutter6D is in The model trained here, on GraspClutter6D.

    What to know when reading it:

    • Inputs derived from ground truth. GraspNet-baseline, Scale-Balanced-Grasp, EconomicGrasp and FineGrasp crop the workspace with the ground-truth segmentation at test time, as their references do; their records are stamped gt_assisted: workspace. HGGD reads the whole image and nothing in its input is derived from ground truth (gt_assisted is empty). The two kinds of row are not like-for-like.
    • The filter of each reference. on is not one setting: every config keeps the collision filter of its method's reference (voxels of 0.005 m for EconomicGrasp and 0.01 m for the others), and HGGD's on row is what its released test script dumps, its own filter followed by NMS. The chain with all its parameters is in each record.
    • Unpaired reported numbers. The HGGD lines "not stated" are, for each camera, the "In paper" and "In repo" rows of its README, in that order. The GraspNet-baseline line is the paper's number as its repository README quotes it ("In paper"); the README says of the "In repo" row only that it adds collision detection. EconomicGrasp's reported numbers are read as filter off: neither its README nor the paper says, and the shipped test command leaves the filter off.
    • One run each. Every number is one run with seed 0. The spread over point-sampling seeds, and for HGGD over its random draws at inference, was not measured on whole splits.
    • The differences are stated, not explained, here. Each method's README (configs/<method>/README.md, section "Results") says for every difference what was investigated and what was not.
    • Not scored. GSNet: the file released with its reference, a third-party implementation, is no reference for the benchmark (configs/gsnet/README.md), so its rows are those of the model trained here, in Trained and evaluated here. GraspNet-baseline, Scale-Balanced-Grasp and FineGrasp have a row for RealSense only.
