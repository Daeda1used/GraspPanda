    Slots: the stages of the pipeline and what can go into each¶

    GraspPanda builds a grasp detector from stages, and every stage is a slot of the config: a place where one component can be replaced by another that keeps the same contract. This page is the map: the pipeline, the task of every slot, its 248 options in all, and which option was measured to work under which method. Every slot has a page of its own with one row and one command per option.

    No accuracy is claimed for any option that is not one of the six ported methods. An option is listed because it was built, trained for 20 iterations on 8 real frames of GraspNet-1Billion and asked to predict (grasppanda probe). That shows it is usable, not that it is good; the model zoo is still empty.

    To try options without reading further, open the combination explorer: pick a method, change a slot, read the measured verdict and the command.

    Words used on these pages¶

    • seed: a point of the scene at which a grasp is predicted; the proposal picks the seeds (1024 per frame in the ported methods).
    • contract: what a component declares about its input and output (where its features live, which axes a tensor has, which labels it reads). The config check compares contracts before anything is built and refuses a mismatch with the fix.
    • preset: a small YAML file with a component and settings for table-top depth clouds; the name after --set <slot>=.
    • adapter: a wrapper compose puts around a scene encoder so that it fits the next stage (features propagated back to every point, or kept on a subsample).
    • dense / compact label set: the grasp labels a head is trained on. Dense is the full grid of GraspNet-1Billion (300 views × 12 in-plane angles × 4 depths per labelled point); compact keeps the best grasp per view (EconomicGrasp, FineGrasp). A head, its assigner and the dataset section must use the same one.
    • point painting: giving every point the image feature at its pixel, which is how a seed-based method reads an image encoder.

    The pipeline¶

    observation: a depth image as a point cloud (HGGD also reads the colour image)
  │
  ├─ the seed-based methods
  │    scene encoder ─► seed proposal ─► view ─► (assigner) ─► grouper ─► head bundle ─┐
  │    features         seeds            approach  labels,       crops                 │
  │                                                training                            │
  └─ HGGD: image encoder ─► heat-map and region stages (no slots of their own yet) ────┤
  grasps for the evaluator or a robot ◄─ post-processing ◄─ GraspGroup ◄───────────────┘

around the model: the loss of every stage · the training recipe

    Six methods are ported. Five share the seed-based skeleton and therefore its six stage slots (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp); HGGD is a detector family of its own with one slot so far, the image encoder. Losses, post-processing and the training recipe are around the stages and apply to all six.

    The slots¶

    An option is a name you can write after --set <slot>=: a preset (a component with settings for table-top depth clouds) or a component with its defaults.

    Slot Task, and input → output Options
    Image encoder
    model.image_encoder    		 Turns the colour (or RGB-D) image into feature maps. HGGD predicts its grasp heat-map from them; a seed-based method can read them at the pixel of every point (point painting).
    image (B, C, H, W) → a list of feature maps, finest first    		 38 (4 component types)
    Scene encoder
    model.backbone    		 The first learned stage of a seed-based method: one feature vector per point of the depth cloud. Its receptive field is what a seed knows before any crop is taken.
    points (N, 3) in metres, camera frame, with per-point features → features on every point (dense) or on a sub-sample (subsampled)    		 47 (29 component types)
    Seed proposal
    model.proposal    		 Decides where grasps are predicted: picks a fixed number of seeds per frame (usually 1024) among the scene points, by a predicted score, a sampler, or both.
    encoder features → SeedSet: seed points, their features, named scores    		 24 (4 component types; 11 samplers as model.proposal.sampler)
    View
    model.view    		 Chooses the approach direction of every seed: two of the three degrees of freedom of the grasp orientation, and the frame the crop is taken in.
    SeedSet → ApproachSet: a unit direction and a rotation per seed, and the index of the label view    		 21 (8 component types)
    Assigner
    model.assigner    		 Training only: matches every seed with the grasp labels of the scene point it sits on, in the label set the head is supervised with.
    seeds, approach, supervision → matched labels (dense grids or compact best grasps), optional seed weights    		 4 (3 component types)
    Grouper
    model.grouper    		 Gathers the neighbourhood of every seed in the frame of its approach direction and turns it into the feature the head reads.
    points with features, crop centres and frames → one feature per seed, or one per seed and depth bin    		 32 (14 component types)
    Head bundle
    model.head    		 Predicts the grasp at a seed: in-plane rotation, depth, width and score. Network head, target encoder, loss and decoder share one parameterisation, so they are swapped as a whole.
    crop features → loss terms in training; GraspGroup (one grasp per seed) at prediction    		 10 (4 component types)
    Loss
    model.<stage>.<term>_loss    		 One term of the loss of a stage (objectness, graspness, view score, grasp score, angle, depth, width). A stage declares the kind of each term, a loss the kinds it fits.
    prediction and target of one term → a weighted scalar    		 20 (18 component types)
    Post-processing
    evaluation.variants.<name>    		 What happens to predicted grasps before an evaluator or a robot gets them: filters, selection, corrections of pose and width, a change of frame. Steps are chained.
    GraspGroup of one frame and the observation → GraspGroup    		 15 (14 component types)
    Training recipe
    optimizer, scheduler, hooks, data.train.dataset.transforms    		 Everything around the model: how weights are updated, how the learning rate moves, what runs around the loop, how a training sample is perturbed.
    parameters and gradients → updates; a training sample → a perturbed sample    		 37 (19 component types)

    The assigner has no page of its own: it goes with the head bundle and the label set (Heads and losses, Data contracts). The scene encoders have an overview and three pages: point-based networks, sparse-voxel networks and released weights, transformers and pretrained 3-D encoders. The encoders ported before these pages are in Scene encoders of the model zoo.

    Which option fits which method¶

    From the measured records (1262 recorded cells: 1014 runs, 174 runs-empty, 29 runs-unstable, 41 refused, 4 fails), with one slot replaced at a time. Every method has a page that lists the options of each of its slots with what was measured for each, and so does grasppanda compose <method config> --list <slot>: GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp, HGGD.

    One run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. A cell (one option under one method) is decided at four levels, each from its record alone; every level needs the one before it:

    • composes: the contract rules and the config check accept the composed config: grasppanda compose writes it (any verdict but refused). A refusal by policy is undecided (needs consent), and so is a request that is not a combination.
    • runs: the probe ran clean on real frames: the verdict runs or runs-empty. A runs-unstable probe counts as not running only when its repeat (repeat in the record: the same config, seed and schedule) was unstable too; without a repeat the level is undecided (unstable, not repeated); when the repeat ran clean the cell runs, and learns and predicts are read from the repeat. fails does not run.
    • learns: judge 2 only. Every loss term was active (reported, finite, not exactly 0) in at least 50 % of the iterations and fell by at least 5 % (fall = (first - mean of the last quarter) / |first| over its active iterations), and no term is flagged flat, rising or constant; a term that is 0 at the last iteration (zero_at_end) is judged on its active iterations. Every unit with trainable parameters received a gradient (no_gradient is empty) and every part changed (unchanged is empty).
    • predicts: judge 2 only. Every predicted frame has at least one grasp, and on every frame the smallest and the largest score differ (score_quantiles): a model whose scores collapsed to one value ranks nothing.

    A level that cannot be decided from a record says why:

    • not checked: the record was judged by the first judge, which recorded neither the trend of the loss terms nor the scores of the predicted grasps.
    • unstable, not repeated: the probe was runs-unstable and has not been repeated: an unstable run counts as not running only when a second probe of the same config is unstable too.
    • needs consent: refused by a policy that waits for the user's consent (trust_remote_code needs accept_remote_code: true): a rule about this machine, not about the combination.
    • not a combination: the request names a component that lacks an option only a preset supplies: it is refused before any contract is compared, and is no combination.
    • not probed: the grid has the cell, but no record yet.
    • not reached by the method as shipped: the method as shipped, probed the same way, does not reach this level either (for example FineGrasp at the constant rate, whose fusion of crop scales gives every seed one feature in a short run, so every grasp gets one score): under that method the level says nothing about the option at this budget.

    The class of an option at a level counts the methods under which it reached that level. For a stage of the seed-based skeleton decided under all five seed-based methods (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp):

    • universal: it reached the level under all five seed-based methods.
    • most: under three or four of them.
    • some: under two.
    • specific: under exactly one.
    • none: under none of them.

    An option of another slot (post-processing, loss, recipe, image encoder) is universal only when it reached the level under every method it applies to and those include the five seed-based ones. Every other class reads N of M probed: it reached the level under N of the M methods where the level was decided, and the methods where it was not are named after it (+2 not checked). A level that no method decided is named by the reason. A level decided only where the level before it failed is not checked: the class says so instead of counting the failures again.

    † The slot was not probed under the five seed-based methods but under the methods of the second column, so its classes count those. (defaults): the component named by its type and built with its constructor defaults, not a preset; a component that needs an option only a preset supplies does not work that way.     How to read it:

    • A class is not a ranking. universal at a level says that a swap reached that level under every method without anything else changed; it says nothing about accuracy.
    • An option that is not universal is usually bound to its neighbours, not to a paper. A head bundle goes with the assigner and the label set it is supervised with, a grouper with the axes its head reads, a scoring proposal with the stage that owns objectness. Replaced together with what they depend on they run under other methods too: see Sets of stages and Several slots at once.
    • A refusal comes with the fix. grasppanda compose prints the contract that is violated and the option or preset that satisfies it, before anything is built.
    • A loss or a recipe preset with a class N of M probed below M did not run everywhere it was put: the loss and recipe pages say where and why (a term of another kind, a detector that reads images, mixed precision).
    • What was not probed is not classified. Most combinations of two or more options have no record; the explorer shows for any two options what the config check answers, which is a weaker statement than a probe.

    How to try one¶

    grasppanda compose --list grouper                                # the presets of a slot
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list grouper
                                                                 # ... under GSNet, measured
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set grouper=roi-grid -o gsnet_roi-grid.yaml                 # a checked config
grasppanda probe gsnet_roi-grid.yaml                             # 20 iterations on
                                                                 # real frames: runs?
grasppanda train gsnet_roi-grid.yaml                             # the real run
    • Several --set go into one command (--set backbone=point-transformer-v2 --set grouper=cylinder-vector-attention, a recorded combination); compose inserts the adapter the contracts ask for and says so, or refuses with the conflict and the fix.
    • grasppanda compose --show grouper=roi-grid prints one preset with what must be re-tuned; grasppanda components --slot groupers prints the contracts, sources and optional libraries of every component.
    • grasppanda explore serves the explorer locally and checks any selection with the compose of your installation.
    • probe needs GraspNet-1Billion and the label assets of the method (Try a combination lists the prepare commands). An option that is a bridge to a library names the extra to install on its slot page. Until the first release on PyPI, install an extra from the repository root with pip install -e ".[<extra>]": the form pip install "grasppanda[<extra>]" resolves against the metadata of the copy that is already installed and may install nothing.
    • Under Scale-Balanced-Grasp a probe ends as wired (a synthetic scene, exit status 3) unless it is given the reference's width histogram: grasppanda probe <config> --opts data.train.dataset.scale_statistic.source=legacy_import data.train.dataset.scale_statistic.reference_sha256=<SHA-256>. The histogram is a statistic of a whole training split and cannot be built from the eight frames of a probe (configs/scale_balanced_grasp/README.md says how to import the file); the recorded runs of that method were measured this way.
    • grasppanda compose --list image_encoder lists the image encoders (the slot of HGGD); the seed-based methods read one through point painting.
