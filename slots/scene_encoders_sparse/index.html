    Scene encoders: sparse-voxel networks and released weights¶

    Words such as seed, contract, preset, adapter, label set and point painting are explained in the slot index.

    Which of these options fit a method

    Every method has a page that lists the options of each of its slots with what was measured for each (the verdict, the levels composes, runs, learns and predicts, the class, the grasps, the reason of a refusal): GSNet (scene encoder); EconomicGrasp (scene encoder); FineGrasp (scene encoder); GraspNet-baseline (scene encoder); Scale-Balanced-Grasp (scene encoder). In a terminal: grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list backbone.

    Class: one run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. Where this page names a class or a measured verdict, it is one of the measured classes.

    This page is about one config line, model.backbone, for the encoders that run on a voxel grid (sparse convolutions, and the point transformers that serialise voxels), and about starting them from published checkpoints. Point-based encoders (PointNet++, PointNeXt) and image encoders have their own pages.

    Nothing here is a grasp-detection result. Every option below was built, loaded (where it has weights) and probed for twenty training iterations on real GraspNet-1Billion frames; no option has been trained to convergence in GraspPanda and no AP is claimed for any of them.

    1. The task of the slot¶

    The scene encoder is the first learned stage of a seed-based grasp detector (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp). It receives the partial point cloud of one depth view, a cluttered table top seen by one camera, and returns one feature vector per point. Everything after it reads those features: the proposal stage scores every point ("is there a grasp here?") and picks about a thousand seeds, the view stage chooses an approach direction per seed, the grouper crops a neighbourhood per seed and the head regresses the grasp. The encoder is therefore the only stage that sees the whole scene, and the only one that can know that a point lies on the rim of a bowl next to a box.

    depth view ─► points ─► [ backbone ] ─► proposal ─► view ─► grouper ─► head ─► grasps
                          this page      seeds      approach   crops     6-DoF

    2. Input and output¶

    Read from grasppanda/models/base.py (Backbone) and grasppanda/models/detectors/seed_based.py.
    Call backbone(points, feats) -> PointFeatures
    points PointSet: (N, 3) float coordinates in metres, camera frame, of all clouds of the batch packed one after another, with batch offsets. N is 15 000 per frame under GSNet and 20 000 under the other methods.
    feats (N, in_channels) float. With point_features: ones (GSNet, EconomicGrasp, GraspNet-baseline, Scale-Balanced-Grasp) it is a constant 1 in every channel: the network sees geometry only, through the voxel grid. With point_features: observation (FineGrasp) it is the 6 real channels of the dataset, and compose sets in_channels: 6.
    Returns PointFeatures: (N, out_channels) bound to the point set they live on.
    output "dense": one feature for every input point (all encoders of this page), or "subsampled": features on a child set of about 1024 points (PointNet++).
    Attributes in_channels, out_channels: the detector builds proposal, view stage and grouper with in_channels = backbone.out_channels.

    What the neighbours require:

    • A proposal states requires = "dense", "subsampled" or "any". GraspNet-baseline and Scale-Balanced-Grasp take seeds from a sub-sampling encoder; compose then wraps a dense encoder in the adapter FurthestPointSubsample (and tells you).
    • The width is free, with one exception: the grouper of Scale-Balanced-Grasp (DepthCylinderGroup with a gated seed residual) adds seed features to 256-channel crop features. Encoders with a free out_channels (SparseUNet14, SpUNet, MinkUNet) are set to the width of the encoder they replace. PTv3 and LitePT have a fixed width; for them compose puts DepthCylinderProjectionGroup in place of that grouper and says so (the width is a contract the config check compares; Grouper, section 5).

    What a sparse-voxel encoder does with this input, in all classes of this page: it quantises the coordinates to a grid it owns (voxel_size or grid_size, 0.005 m in every preset, the grid of GSNet), runs on one feature per occupied voxel and hands the feature of a voxel back to every point in it. The grid is the encoder's unit of length: a network whose weights were trained on rooms at 0.02 m sees, at 0.005 m, a quarter of the extent per kernel. Sparse convolutions go through the facade grasppanda.ops.sparse (spconv underneath; extra spconv-cu118 and siblings).

    3. Options¶

    "Route" says where the code comes from: A = adapted from a permissive repository (listed in THIRD_PARTY_NOTICES.md), W = released weights loaded into a class the toolbox has, own = written for this code base earlier (see Scene encoders). "Measured fit" is the verdict of grasppanda probe on real frames, in the vocabulary of Measured combinations: runs, runs in FurthestPointSubsample when compose inserted that adapter, runs-unstable. Every option composes under all five seed-based methods; at the level runs the class of each is in the method pages and the measured page (an option whose run was runs-unstable and not repeated is not counted there yet).

    4. How to use each option¶

    4.1 A new encoder under a method¶

    grasppanda compose --list backbone                 # the presets, one line each
grasppanda compose --show backbone=minkunet18a     # one preset with its notes
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=minkunet18a -o gsnet_minkunet18a.yaml
grasppanda probe gsnet_minkunet18a.yaml            # a few iterations on real frames
grasppanda train gsnet_minkunet18a.yaml

    The other four methods: economicgrasp/economicgrasp_sunet14_g1b-realsense_10e, finegrasp/finegrasp_sunet14_g1b-realsense_10e, graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e, scale_balanced_grasp/sbg_pointnet2-transformer_g1b-realsense_18e. Under the last two compose wraps the encoder in FurthestPointSubsample by itself:

    $ grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
      --set backbone=minkunet18a-openscene -o gnb_openscene.yaml

    The same as a YAML fragment, for a config written by hand (any member of the family):

    model:
  backbone:
    type: MinkUNet
    in_channels: 3            # what the method feeds: 3 ones, or 6 under FineGrasp
    out_channels: 512         # free 1x1 projection; null returns the decoder width (96)
    voxel_size: 0.005         # the encoder's unit of length, in metres
    layers: [2, 2, 2, 2, 2, 2, 2, 2]
    planes: [32, 64, 128, 256, 128, 128, 96, 96]
    stem_kernel: 5            # 5 in MinkUNet; 3 in the Res16UNet34C checkpoints

    Settings that matter, for all sparse encoders:

    • voxel_size / grid_size: 0.005 m keeps the grid of the reference methods, with about one point per voxel. Weights from room-scale data were trained at 0.02 to 0.025 m; choosing that grid matches the weights and leaves a table-top frame with far fewer voxels (a surface has roughly a sixteenth of them at four times the edge). There is no published answer for grasping; it is the first thing to sweep (--opts model.backbone.voxel_size=0.01).
    • out_channels: the width the later stages are built with. compose keeps the width of the encoder it replaces. For the transformer encoders it is fixed by the architecture.
    • depth against the recipe: the reference recipes (Adam, 1e-3, no warm-up) were tuned for a 14-layer network. Deeper encoders and pretrained ones usually want a lower rate and a warm-up; none of this was tuned here.

    4.2 Starting from released weights¶

    1. Pick a row of table 3.2 and fetch the file into $GRASPPANDA_CACHE/weights_components/. You do not need to look up the link: build the model once and the error prints the command.

      SpUNet: the released weights `gaussiancross-scannet-lin` (GaussianCross (Yao et al., ACM MM 2025);
MIT; 157 MB) are not on this machine. Fetch them with
  mkdir -p $GRASPPANDA_CACHE/weights_components && curl -L -o $GRASPPANDA_CACHE/weights_components/spunet_gaussiancross_scannet_lin.pth https://huggingface.co/RayYoh/GaussianCross/resolve/3cbceee8b88113780cec6a734fea8b14e2baae4f/scannet/semseg-spunet-base-lin/model/model_best.pth
or set `pretrained: null` to build the encoder without them (for example to load a grasp
checkpoint that already holds the encoder).

    2. Compose with the preset of that release, or add two lines to any config of the class:

      model:
  backbone:
    type: SpUNet
    in_channels: 3
    out_channels: 512
    grid_size: 0.005
    pretrained: gaussiancross-scannet-lin   # a name of table 3.2, or a file path
    pretrained_mismatch: skip               # see below

    3. Read the load report in the log. It names every tensor that did not come from the file. These are the reports of three presets, as printed:

      SpUNet: pretrained weights from $GRASPPANDA_CACHE/weights_components/spunet_gaussiancross_scannet_lin.pth (prefix `module.backbone.`): 353 tensors loaded; 2 absent from the file (final.weight, final.bias); 1 of another shape (conv_input.0.weight (32, 5, 5, 5, 6) in the file, (32, 5, 5, 5, 3) here); 2 tensors outside the encoder ignored
MinkUNet: pretrained weights from $GRASPPANDA_CACHE/weights_components/minkunet18a_openscene_scannet_openseg.pth.tar (prefix `net3d.`): 288 tensors loaded; 1 absent from the file (final.bias); 1 of another shape (final.weight (768, 96) in the file, (512, 96) here)
PTv3: pretrained weights from $GRASPPANDA_CACHE/weights_components/ptv3_ppt_s3dis.pth (prefix `module.backbone.`): 507 tensors loaded; 1 of another shape (embedding.stem.conv.weight (32, 5, 5, 5, 6) in the file, (32, 5, 5, 5, 3) here); 5 tensors outside the encoder ignored

    How the option behaves:

    • What is loaded. The encoder alone. The loader finds the prefix under which the file keeps it (module.backbone., net3d., model.backbone., none), ignores heads and optimiser state, and re-lays kernels where the original library stores them differently (Pointcept 1×1 kernels for SpUNet, MinkowskiEngine kernels for MinkUNet).
    • pretrained_mismatch: error (the default) refuses when a tensor of the encoder is absent from the file or has another shape there. Use it with the options of table 3.2 to be sure that everything came from the file.
    • pretrained_mismatch: skip keeps the initialisation of exactly those tensors and lists them. A grasp model needs it almost always, because of two layers: the stem (the releases read 6 or 9 real channels, colour and normal; the grasp methods feed 3 ones) and the final projection when out_channels differs. Everything between them is loaded.
    • No pickled code runs. Training checkpoints of research code pickle schedulers and numpy scalars; the reader maps every such name to an inert object and reads only tensors.
    • Prompt-driven normalisation (ptv3-ppt): the checkpoint holds three sets of normalisation layers, one per training dataset. pretrained_condition: 0 | 1 | 2 takes one set; the model itself is a plain PTv3.
    • Encoder-only PTv3 (ptv3-encoder): enc_mode: true builds no decoder and returns the encoder stages concatenated on every voxel (concat_stages). With pretrained: a full checkpoint loads its encoder half; the report lists the 200 decoder tensors as "in the file but not in the model".

    5. Pitfalls met while building this¶

    • A grasp checkpoint still wants the released file. pretrained loads when the encoder is constructed, also when you then load a grasp checkpoint with --weights or resume a run. Keep the file in place, or set pretrained: null for evaluation (the grasp checkpoint holds the whole encoder).
    • The stem is the tensor that does not load, and it is the layer that reads the input. Under FineGrasp compose sets in_channels: 6, so a 6-channel stem does load there, but nothing says that the six channels of that method are the colour and normal, in the scaling, the release was trained on. Loading says nothing about meaning.
    • The default Concerto files are not the paper's Concerto. The model card calls concerto_{tiny,small,base,large}.pth pre-release Utonia models; the paper's model is concerto_base_origin.pth. The card also says the default files accept inputs without colour and normal ("please set them to zeros"), which is closer to what a grasp model has.
    • Licences differ inside one family. PTv3 and LitePT weights are MIT; Sonata and Concerto weights are CC BY-NC 4.0 (the Sonata hub card states no licence, the repository README does). PointContrast, Mask3D and OpenScene publish code under MIT or Apache-2.0 and say nothing about the weights, which were trained on ScanNet.
    • SpUNet is not MinkUNet34C. Same block counts and widths; in Pointcept's network the stride-2 convolution changes the width, in MinkowskiEngine's the first block of the stage does. A checkpoint of one does not fit the other; the loader says "no tensor fits" or lists hundreds of mismatches rather than loading half of it.
    • Two kernel sizes may not share a spconv indice key. A 5³ stem that shared the key of the 3³ blocks of its level built, ran on CPU with a 3³ stem and failed on the GPU with you must provide same algo to layers share same indice key. The stem of MinkUNet has its own key; the unit test runs a 5³ stem.
    • Fixed-width encoders under Scale-Balanced-Grasp used to fail when the model was built (the gated seed residual adds the seed features to 256-channel crop features). The config check compares the widths now and compose puts the projected grouper in place; with --no-adapter the pair is refused with the fix.
    • Old checkpoints in the legacy (non-zip) PyTorch format that pickle foreign objects cannot be read without executing them and are refused (met with the Contrastive Scene Contexts files). Re-save the state dict in the environment that wrote it.
    • Probes on a shared GPU. Several cells first "failed" with CUDA out of memory because other jobs held the card; such records say nothing about the config and were probed again.
