    Scene encoders: transformers and sequence models¶

    Seed-based · 5 methods--set backbone=16 options

    These encoders attend over points, voxels, octree nodes or point patches: the Point Transformer line (V1 to V3, with Sonata, Concerto and Utonia weights), LitePT, Volt, OctFormer, and the point-patch tokens of PointViT, PointMamba and Uni3D. What all scene encoders share is on the overview.

    Use it¶

    grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
    --set backbone=ptv3 -o graspnet-baseline_ptv3.yaml
grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e --list backbone

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=ptv3 -o gsnet_ptv3.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list backbone

    grasppanda compose scale_balanced_grasp/sbg_pointnet2-transformer_g1b-realsense_18e \
    --set backbone=ptv3 -o scale-balanced-grasp_ptv3.yaml
grasppanda compose scale_balanced_grasp/sbg_pointnet2-transformer_g1b-realsense_18e --list backbone

    grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e \
    --set backbone=ptv3 -o economicgrasp_ptv3.yaml
grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e --list backbone

    grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --set backbone=ptv3 -o finegrasp_ptv3.yaml
grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e --list backbone

    The first command writes a checked config; the second lists every option of the slot under that method, with what was measured. Then grasppanda probe <file> tries the config on real frames and grasppanda train <file> trains it (Swap a component). Each method page lists the same: GraspNet-baseline · GSNet · Scale-Balanced-Grasp · EconomicGrasp · FineGrasp.

    What the columns say, and who is left out
    • Runs: out of the methods the option is a swap under, those under which its probe trained on real frames without error. A method that ships the option is named own and not counted; a method still undecided is counted and named. Measured on 20 training iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, one run per cell; nothing was measured on GraspClutter6D or on Kinect frames.
    • Trains like shipped: out of the methods under which the swap ran, those under which every comparable loss term ended within the method's tolerance of the component it ships, with nothing rising; a method left out is named with why. Measured on 250 iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, at a constant learning rate (FineGrasp: its own warm-up), beside the method as shipped trained the same way twice.
    • How we measure defines every word of these columns.

    • ptv3-sonata, trains like shipped: diverging under FineGrasp; not compared under GSNet, EconomicGrasp: the swap did not run at level 1.

    Choosing¶

    • Serialised voxels: ptv3 and litept run on the 5 mm grid of the sparse encoders and come with released weights (ptv3-scannet200, ptv3-ppt, litept-structured3d; the Sonata weights are non-commercial).
    • The unit of length is a setting of every encoder here: grid_sizes of point-transformer-v2, grid_size × kernel_size (the token edge) of volt, voxel_size of octformer; point-transformer-v1 sub-samples by ratio and has none.
    • Point-patch tokens (point-vit, point-mamba, uni3d) were designed for single objects; their tokens become the seeds, and num_group must equal the seeds of the method.
    • Attention cost: point-vit attends globally (quadratic in the tokens), point-mamba is linear but runs on CUDA only.
    • The encoders checked against their authors' code (PTv3, its Sonata and Utonia variants, LitePT) are on Encoders checked against their authors' code.

    Details¶

    The settings that matter

    Point Transformer V2: grid_sizes is the cell edge of the four poolings, in metres; the class defaults are for rooms, the preset divides the ScanNet values by 4.

    model:
  backbone:
    type: PointTransformerV2
    grid_sizes: [0.015, 0.0375, 0.09375, 0.234375]   # metres

    Volt: grid_size × kernel_size is the edge of a token (2.5 cm in the preset); smaller tokens resolve finer geometry and cost quadratically more attention. embed_dim / num_heads must be 64. The authors state that Volt overfits without their training recipe (strong augmentation, distillation, EMA), which is not part of this toolbox.

    OctFormer (extra ocnn): voxel_size is the edge of an octree leaf; a frame must fit a cube of voxel_size * 2**octree_depth; patch_size octree nodes form one attention group.

    PointViT, PointMamba, Uni3D (extras mamba-ssm for PointMamba, timm for Uni3D):

    model:
  backbone:
    type: PointViT                 # or PointMamba, or Uni3D
    num_group: 1024                # tokens per cloud = points with features = seeds
    group_size: 32                 # nearest points per token (Uni3D: 64)
    coord_scale: 2.0               # metres -> the unit-sphere scale of the object models

    PTv3 and LitePT take the sparse grid (grid_size) and, with pretrained:, a release by name (below). ptv3-encoder sets enc_mode: true: no decoder, the encoder stages concatenated on every voxel. ptv3-ppt holds one set of normalisation layers per training dataset; pretrained_condition picks one. Other files of the same releases (the larger PPT model, the later Sonata file, the large Concerto model, the larger LitePT models) have the same layout and are expected to load the same way; they were not downloaded, so pass such a file as a path.

    Pitfalls met while building this
    • mamba-ssm on PyPI is a source build. Prebuilt wheels per torch, CUDA and Python are on its releases page.
    • import mamba_ssm compiles a Triton helper and fails with cannot find -lcuda when the machine has libcuda.so.1 but no libcuda.so: point TRITON_LIBCUDA_PATH at a directory with a link of that name.
    • PointMamba has no CPU path; on the CPU it says so.
    • ocnn runs its convolutions on Triton kernels by default, which did not compile here; OctFormer sets ocnn's pure-PyTorch path (conv_method: block_gemm).
    • OctFormer's features depend on the batch: attention groups are counts of z-ordered nodes of the whole batch, as in the reference.
    • The default Concerto files are not the paper's Concerto. The model card calls them pre-release Utonia models; the paper's model is concerto-base-origin.
    • Object checkpoints use other sizes. MaskPoint's ShapeNet file has the Point-BERT layout (token_dim: 256); its ScanNet file is a 3DETR encoder and does not fit PointViT.
    Not wrapped
    Candidate Why not
    Swin3D built on MinkowskiEngine plus its own CUDA package, neither a dependency here.
    Superpoint Transformer / EZ-SP consumes a superpoint partition computed outside the network.
    Mamba3D, Point Cloud Mamba no licence file.
    PointGPT its blocks differ from PointViT's, so its checkpoints need a second block type.
    ReCon, ACT, PCP-MAE, Point-JEPA, Point-BERT's own file checkpoints behind links that were not downloaded; nothing is claimed.
    Point-M2AE a hierarchical encoder, not the shared single-scale layout.
    Point-MoE, D-DITR, LAM3C weights for PTv3 a mixture-of-experts block (Point-MoE); AGPL-3.0 (D-DITR) and non-commercial (LAM3C) weights, not downloaded.
