    Scene encoders: transformers, state-space models, pretrained 3-D encoders¶

    Words such as seed, contract, preset, adapter, label set and point painting are explained in the slot index.

    Which of these options fit a method

    Every method has a page that lists the options of each of its slots with what was measured for each (the verdict, the levels composes, runs, learns and predicts, the class, the grasps, the reason of a refusal): GSNet (scene encoder); EconomicGrasp (scene encoder); FineGrasp (scene encoder); GraspNet-baseline (scene encoder); Scale-Balanced-Grasp (scene encoder). In a terminal: grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list backbone.

    Class: one run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. Where this page names a class or a measured verdict, it is one of the measured classes.

    Slot model.backbone of the seed-based detectors (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp). This page covers the attention-based and sequence-model encoders added from existing code: Point Transformer V1 and V2, Volt, OctFormer, the point-token family (PointViT, PointMamba, Uni3D) and the released weights that fit them. PTv3 (with Sonata, Concerto and Utonia weights), LitePT and the PointNet++ / transformer encoder of Scale-Balanced-Grasp were in the toolbox before; see the backbone zoo.

    Nothing on this page is a grasp-detection result. Every option was built, trained for 20 iterations and used for prediction on real GraspNet-1Billion frames under each method (a probe); no AP was measured for any of them, and no released weight was evaluated on grasp data.

    1. The task of the slot¶

    The scene encoder turns the point cloud of one depth frame into per-point features. Everything after it reads those features: the proposal stage scores points and picks seeds, the view stage chooses an approach direction per seed, the grouper crops a neighbourhood per seed and the head predicts angle, depth, width and score. The encoder is the only stage that sees the whole scene, so it decides how much context a seed feature carries and most of the model's cost.

    Observation.points ──► backbone ──► proposal ──► view ──► grouper ──► head ──► GraspGroup
     PointSet        PointFeatures    SeedSet   ApproachSet GroupFeatures

    2. Input and output¶

    class Backbone(nn.Module):                      # grasppanda/models/base.py
    output: ClassVar[Literal["dense", "subsampled"]]
    in_channels: int
    out_channels: int
    def forward(self, points: PointSet, feats: Tensor) -> PointFeatures: ...
    points PointSet: coords (N, 3) float32, metres, camera frame, all clouds of the batch concatenated; batch_offsets (B + 1,) marks the clouds. The shipped GraspNet-1Billion pipelines sample 15 000 or 20 000 points per frame after a workspace crop; clouds of a batch may differ in size.
    feats (N, in_channels) per-point input features, or None when in_channels == 0. The detector feeds constant ones (point_features: ones, in every shipped method except FineGrasp) or what the dataset provides (point_features: observation).
    returns PointFeatures: feats (M, out_channels) bound to a point set.
    output = "dense" M == N: one feature per input point, bound to points itself.
    output = "subsampled" M < N: features on points.subset(index), a child set that remembers which rows of the parent it kept. An equal number of points per cloud.

    What the neighbours require, and what the config checker does with it:

    • The proposal stage declares requires. GSNet, EconomicGrasp and FineGrasp score every scene point (GraspnessFPS: dense); GraspNet-baseline and Scale-Balanced-Grasp take the encoder's subsample as their seeds (SubsampledSeeds: subsampled, and the number of kept points must be proposal.num_seeds, 1024).
    • A mismatch is refused before anything is built, and the message names the adapter: FeaturePropagation (three-neighbour interpolation back to every point) makes a subsampled encoder dense; FurthestPointSubsample makes a dense encoder subsampled. grasppanda compose inserts the adapter itself and says so.
    • out_channels is the in_channels of proposal, view stage and grouper, injected by the detector. Scale-Balanced-Grasp adds seed features to crop features, so there the encoder must be exactly as wide as the crop features (256). Every encoder of this page has an out_channels option, which compose sets to the width of the encoder it replaces (512 under the sparse U-Net methods, 256 under the PointNet++ methods).
    • Features must not mix clouds of a batch. All encoders here keep that in evaluation mode, with two documented exceptions: OctFormer (attention groups are cut from the nodes of the whole batch, as upstream) and, within float noise of its CUDA kernel, PointMamba.

    4. How to use each option¶

    One command composes a config, a second one probes it:

    $ grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=volt -o gsnet_volt.yaml
$ grasppanda probe gsnet_volt.yaml

    compose prints what it changed. Two real examples, the same encoder under a method that wants subsampled features and under one that wants dense ones:

    $ grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e --set backbone=point-vit -o baseline_point-vit.yaml

slot      component             from
────────  ────────────────────  ──────────────────
backbone  PointViT              preset `point-vit`
proposal  SubsampledSeeds       base config
...
what compose did
  • backbone: preset `point-vit` (PointViT). Plain transformer over 1024 point-patch tokens (the
    Point-BERT / Point-MAE encoder).
  • out_channels: 256, the output width of the encoder it replaces (PointNet2), so that the other
    stages keep the width they have in the base model and the encoder is the only stage that
    differs.
config check
  ✓ valid  (hash 5d1fec9f95b3)

$ grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=point-vit -o gsnet_point-vit.yaml

slot      component                       from
────────  ──────────────────────────────  ─────────────────────────────────────────────────────
backbone  PointViT in FeaturePropagation  preset `point-vit`, in the adapter FeaturePropagation
...
  • wrapped PointViT in the adapter FeaturePropagation (preset `feature-propagation`): GraspnessFPS
    requires 'dense' scene features, but PointViT returns 'subsampled' ones (features on a
    sub-sampled point set). An adapter changes the model; its notes below say how.

    To change an option of the preset, add --opts model.backbone.<option>=<value> to compose, or write the fragment into your own config. The fragments below are the presets; the comments say which settings matter.

    Point Transformer V1¶

    model:
  backbone:
    type: PointTransformerV1
    in_channels: 3                 # constant ones
    out_channels: 512              # optional projection; omit for the 32-channel decoder
    # blocks: [1, 2, 3, 5, 2]      # Seg50, the model of the paper (default: Seg26)

    No metric setting: sub-sampling is by ratio (÷4 per stage), neighbourhoods are 8 or 16 nearest points. A cloud needs at least 256 points (the product of the strides).

    Point Transformer V2¶

    model:
  backbone:
    type: PointTransformerV2
    in_channels: 3
    out_channels: 512
    grid_sizes: [0.015, 0.0375, 0.09375, 0.234375]   # metres; the ScanNet values ÷ 4

    grid_sizes is the setting that matters: the cell edge of the four poolings, in metres. The class defaults (0.06 … 0.94 m) are for rooms. pe_multiplier: true gives the paper's PT-v2m1 attention; the default is PT-v2m2, which the Pointcept README recommends.

    Volt¶

    model:
  backbone:
    type: Volt
    in_channels: 3
    out_channels: 512
    up_mlp_dim: 128
    grid_size: 0.005               # voxel edge, metres
    kernel_size: 5                 # voxels per token and axis: tokens of 2.5 cm
    embed_dim: 384                 # Volt-S; 768 with num_heads: 12 is Volt-B
    num_heads: 6                   # embed_dim / num_heads must be 64 (rope_split)
    qk_norm: true

    grid_size × kernel_size is the edge of a token. Smaller tokens resolve finer geometry and cost quadratically more attention. The authors state that Volt overfits without their training recipe (strong augmentation, distillation from a sparse U-Net, EMA); that recipe is not part of this toolbox.

    OctFormer¶

    $ pip install -e ".[ocnn]"

    model:
  backbone:
    type: OctFormer
    in_channels: 3
    out_channels: 512
    voxel_size: 0.005              # edge of an octree leaf, metres
    # octree_depth: 11             # a frame must fit a cube of voxel_size * 2**depth
    # patch_size: 26               # octree nodes per attention group
    # drop_path: 0.5               # the ScanNet recipe; lower it for short schedules

    PointViT, PointMamba, Uni3D (point-patch tokens)¶

    $ pip install -e ".[timm]"         # Uni3D
$ pip install -e ".[mamba-ssm]"    # PointMamba; or a wheel from the mamba releases page

    model:
  backbone:
    type: PointViT                 # or PointMamba, or Uni3D
    in_channels: 0                 # coordinates only (Uni3D: 3, colour or constant ones)
    num_group: 1024                # tokens per cloud = points with features = seeds
    group_size: 32                 # nearest points per token (Uni3D: 64)
    coord_scale: 2.0               # metres -> the unit-sphere scale of the object models
    # PointViT:   embed_dim: 384, depth: 12, num_heads: 6, token_dim: 384 (256: Point-BERT)
    # PointMamba: serialization_grid: 0.02, ssm_cfg: {d_state: 16}
    # Uni3D:      timm_model: eva02_small_patch14_224

    num_group must equal proposal.num_seeds under GraspNet-baseline and Scale-Balanced-Grasp (1024 in the shipped configs). PointViT attends globally (quadratic in num_group); PointMamba is linear in it.

    5. Released weights¶

    Weights of scene encoders are never downloaded by the toolbox. Download a file, convert it for the config you composed, and start training from it:

    $ curl -L -o pretrain.pth https://github.com/Pang-Yatian/Point-MAE/releases/download/main/pretrain.pth
$ python -m tools.convert_encoder_checkpoint pretrain.pth point-mae_for_baseline.pth --config baseline_point-vit.yaml
pretrain.pth: 156 tensors fit PointViT (as `backbone.*`), 53 dropped (decoders, tokens, heads)
  left at their initial values: proj.weight, proj.bias
wrote point-mae_for_baseline.pth
$ grasppanda train baseline_point-vit.yaml --opts runtime.load_from=point-mae_for_baseline.pth runtime.allow_weight_mismatch=true

    A probe started from that file ran (the trainer lists the keys the file does not hold):

    $ grasppanda probe baseline_point-vit.yaml --opts runtime.load_from=point-mae_for_baseline.pth runtime.allow_weight_mismatch=true
    loss                        3.411 → 1.342
  predicted   2 frame(s) · 493, 482 grasps

    What these weights are and are not:

    6. Pitfalls met¶

    • mamba-ssm on PyPI is a source build. Prebuilt wheels per torch / CUDA / Python version are on the releases page; mamba_ssm-2.3.2.post1+cu11torch2.7cxx11abiTRUE-cp312 was used here (installed with --no-deps).
    • import mamba_ssm compiles a Triton helper and fails with /usr/bin/ld: cannot find -lcuda when the machine has libcuda.so.1 but no libcuda.so. Point Triton at a directory that holds a link of that name: mkdir libcuda && ln -s /usr/lib/x86_64-linux-gnu/libcuda.so.1 libcuda/libcuda.so && export TRITON_LIBCUDA_PATH=$PWD/libcuda.
    • PointMamba has no CPU path (the selective scan is a CUDA kernel). On the CPU it raises PointMamba runs on CUDA only ...; its unit tests need a GPU.
    • ocnn 2.3.3 runs its 3×3×3 convolutions on Triton kernels by default on CUDA; with the Triton 3.3.1 of this environment they did not compile (triton.compiler.errors.CompilationError). OctFormer therefore sets ocnn's pure-PyTorch path (conv_method: block_gemm); conv_method: triton asks for the kernels. import ocnn itself needs triton to be importable.
    • OctFormer's features depend on the batch: attention groups are fixed counts of z-ordered nodes of the whole batch, so where a group starts inside a frame depends on the frames before it. This is the reference behaviour.
    • Object checkpoints use other sizes than the first config you try. MaskPoint's ShapeNet file has the Point-BERT layout (token_dim: 256); MaskPoint's ScanNet file (pretrain_scannet_medium_enc12x.pth) is a 3DETR encoder and does not fit PointViT (2 of 156 tensors matched).
    • Width under Scale-Balanced-Grasp. An encoder that returns 32 channels is refused at build time by the gated seed residual of DepthCylinderGroup (it met PointTransformerV1 before that class had out_channels). Keep out_channels at the value compose sets.
    • Memory at scene size (one forward and backward pass, 35 000 points in two clouds, random weights, RTX A6000 shared with other jobs; a rough guide, not a benchmark): PointTransformerV1 1.4 GiB, PointTransformerV2 6.2 GiB, Volt (Volt-S, 2.5 cm tokens of a 0.6 × 0.6 m slab) 2.1 GiB, OctFormer 1.0 GiB (leaves of 1 cm), PointViT 2.7 GiB, PointMamba 2.6 GiB.
