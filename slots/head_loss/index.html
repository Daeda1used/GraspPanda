    Grasp heads and losses: what is predicted per seed and how it is penalised¶

    Words such as seed, contract, preset, adapter, label set and point painting are explained in the slot index.

    Which of these options fit a method

    Every method has a page that lists the options of each of its slots with what was measured for each (the verdict, the levels composes, runs, learns and predicts, the class, the grasps, the reason of a refusal): GSNet (head bundle, assigner, losses); EconomicGrasp (head bundle, assigner, losses); FineGrasp (head bundle, assigner, losses); GraspNet-baseline (head bundle, assigner, losses); Scale-Balanced-Grasp (head bundle, assigner, losses). In a terminal: grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list head.

    Class: one run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. Where this page names a class or a measured verdict, it is one of the measured classes.

    1. The task of the slot¶

    A seed-based detector (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp) picks seed points, chooses an approach direction per seed, crops the scene around the seed along that direction, and then has to say which grasp to execute there: the in-plane rotation, how deep the fingers go, how wide they open, and how good the grasp is. That last step is the head bundle (model.head). It is the last stage of the network: grouper → head → GraspGroup.

    A head bundle is four parts that cannot be mixed across bundles, because they share one grasp parameterisation: the network head, the target encoder (labels → what the head is trained on), the loss, and the decoder (outputs → grasps). So the bundle is swapped as a whole. Inside a bundle, and inside the proposal and view stages before it, every loss term is a small config node of its own ({type: SmoothL1, weight: 10.0}); those are swapped one by one. This page covers both: head bundles, and the loss primitives that go into the loss terms of any stage.

    No AP is claimed for any option of this page. What was checked is that each one builds, trains a few iterations on real frames with finite losses and predicts (the measured records), and a unit test of its contract.

    2. Input and output¶

    The head bundle¶

    class HeadBundle(nn.Module):
    def forward(self, crops: GroupFeatures) -> Predictions: ...        # raw outputs, with gradients
    def encode(self, matched: MatchedLabels, ...) -> Targets: ...      # labels -> targets
    def loss(self, predictions, targets, ...) -> dict[str, Tensor]:    # named, weighted terms
    def decode(self, raw, seeds, approach, gripper) -> GraspGroup: ... # one grasp per seed
    in: crop features from the grouper, one row per valid seed. Their named axes are the grouper's out_axes: ('seed', 'channel') (CylinderGroup, CylinderInteractionGroup, MultiScaleGroup) or ('seed', 'depth', 'channel') (DepthCylinderGroup, one crop per depth bin).
    in: matched labels from the assigner, the labels of the scene point nearest to every seed, already reduced to the chosen view: dense (a friction and a width per in-plane angle and depth bin) or compact (one best grasp per seed).
    out, training a dictionary of named loss terms, each already multiplied by its weight; the trainer sums them and logs each as loss/<name>.
    out, prediction a GraspGroup with one grasp per seed: translation (the seed, metres, camera frame), rotation (approach from the view stage, in-plane angle from the head), depth, width (metres), score.

    Contract attributes of a head bundle, and what the config checker does with them:

    attribute meaning rule
    in_axes axes of the crop features it expects must equal the grouper's out_axes
    label_format dense or compact must equal the assigner's label_format (and the dataset must serve that label set)
    score_kind meaning of the decoded score scores of different kinds are not comparable; shown in the catalogue
    applies_seed_weights whether its loss honours a weight per seed from the assigner an assigner that returns weights needs a head that applies them
    loss_terms loss option → kind of term (below) every loss node is checked against it

    A loss primitive¶

    class Loss(nn.Module):
    def forward(self, prediction, target, mask=None, weights=None) -> Tensor  # weight x mean over the supervised elements

    A stage declares the kind of every loss option it has, a primitive the kinds it accepts. There are four kinds:

    kind what the stage hands to the loss examples
    class (N, C) logits against (N,) class indices objectness of points or seeds; angle, depth and quality classes
    unit prediction and target of equal shape, the target a quality in [0, 1] graspness, view scores of TemplateViewStage, the score grid of SWADHead
    value prediction and target of equal shape, the target unbounded widths, tolerances, the log-friction scores of the GraspNet-baseline family (up to ln 10)
    bins (N, C) logits over bins against (N,) fractional bin positions the width of DecoupledGridHead with width: bins

    Which term of which stage is which kind (the stages of the five shipped methods):

    stage option (write it as <slot>.<option>) kind loss in the shipped configs
    GraspnessFPS (GSNet, EconomicGrasp, FineGrasp) proposal.objectness_loss class CrossEntropy
    proposal.graspness_loss unit SmoothL1
    TemplateViewStage (GSNet, EconomicGrasp, FineGrasp) view.loss unit SmoothL1
    LatticeViewStage, IcosphereViewStage, HealpixViewStage (view slot) view.loss unit with target: score, class with target: best_view SmoothL1 / CrossEntropy
    ObjectnessViewStage (GraspNet-baseline, Scale-Balanced-Grasp) view.objectness_loss class CrossEntropy
    view.view_loss value MSE
    SWADHead (GSNet) head.score_loss unit SmoothL1
    head.width_loss value SmoothL1
    EconomicHead (EconomicGrasp, FineGrasp) head.angle_loss, head.depth_loss, head.score_loss class CrossEntropy
    head.width_loss value SmoothL1
    OperationHead (GraspNet-baseline, Scale-Balanced-Grasp) head.angle_loss class CrossEntropy
    head.score_loss, head.width_loss, head.tolerance_loss value SmoothL1
    DecoupledGridHead (new) head.score_loss unit SmoothL1
    head.angle_loss class CrossEntropy
    head.depth_loss class or value (option depth) CrossEntropy / SmoothL1
    head.width_loss value, class or bins (option width) SmoothL1 / CrossEntropy / DistributionFocal

    The config checker refuses a loss in a term of another kind and names the losses that fit. Two further attributes of a primitive matter:

    • prediction: value or logit. A loss that trains the output of a unit term as a logit (QualityFocal, Varifocal, GHMC, FocalLoss, BinaryCrossEntropy) changes what the raw output means. The stages read it through the sigmoid where they consume it: GraspnessFPS compares the graspness with its threshold, SWADHead decodes its score.
    • applies_weights: false for a loss that scores the supervised set as a whole (DiceLoss, LovaszSoftmaxLoss). It is refused in a term that receives a weight per seed from the assigner (Scale-Balanced-Grasp).

    grasppanda components <Loss> prints both and the accepted kinds.

    3. Options at a glance¶

    Losses¶

    "Name" is the preset to write after --set <slot>.<option>=; "component" is the type: of a config node. "Probed" is what the measured records hold (measured combinations, group loss): the terms the loss was put into on real frames, all with the verdict runs unless stated. Every loss goes into every term of a kind it accepts, in any stage of any seed-based method (a contract, not a measured class); that it does is a unit test on tiny models of four methods (tests/unit/test_losses_zoo.py). The measured grid also has a cell for every loss in one term of each kind it fits, under every seed-based method with such a term (the last term of that kind in the pipeline, the one nearest the grasp); the measured page lists those terms and which of the cells are not probed yet. Nothing here has weights.

    Head bundles¶

    "Fit" is the verdict of the measured records (group stage, one stage replaced under the method) for GSNet / EconomicGrasp / FineGrasp / GraspNet-baseline / Scale-Balanced-Grasp. All are randomly initialised; none has released weights.

    Name Component What it is From Fit Why

    swad-focal SWADHead swad with QualityFocal on the score grid and a fixed friction range; the score is decoded through the sigmoid preset of this page runs / refused / refused / refused / refused as swad
    economic EconomicHead angle, depth and quality classes plus a width EconomicGrasp (existed) refused / runs / runs / refused / refused compact labels

    decoupled-grid DecoupledGridHead the score grid of SWAD, but angle and depth come from two classifiers of their own and the width is predicted once per depth bin written here after the idea of the grasp head of FGC-GraspNet (Lu et al., ICRA 2022, arXiv 2206.11141); no upstream code runs / refused / refused / refused / refused dense labels, crops without a depth axis: swaps with swad

    Why the refusals: EconomicGrasp and FineGrasp train on compact labels, which hold one grasp per seed and not the grid a score-grid head is supervised with; GraspNet-baseline and Scale-Balanced-Grasp crop once per depth bin, so their features have a depth axis. The messages say so (section 5). A head preset can be moved to another method together with the stages it depends on, e.g. under GraspNet-baseline --set view=template-view --set grouper=CylinderGroup --set head=decoupled-grid (accepted by compose; not probed); which stage sets are legal is in swapping components.

    Assigners¶

    The assigner matches every seed to a grasp label during training and hands the matched labels to the view stage and the head bundle, so it is chosen with the head and the label set, not on its own. "Fit" is the verdict of the measured records (group stage, the assigner alone replaced) for GSNet / EconomicGrasp / FineGrasp / GraspNet-baseline / Scale-Balanced-Grasp; "shipped" marks the method that ships it.

    Name Component What it is Label set Fit Why
    NearestLabelAssigner (constructor defaults; no preset) NearestLabelAssigner every seed takes the labels of the nearest label point of its object; every seed is supervised dense runs (shipped) / refused / refused / refused / refused compact-label heads read another label set; ObjectnessViewStage reads on_object and view_width, which the defaults do not return
    nearest-label-object-seeds NearestLabelAssigner the same matching, only seeds on an object supervised, crops at the matched label point (GraspNet-baseline) dense runs / refused / refused / runs (shipped) / runs EconomicHead is supervised with compact labels
    compact-label CompactLabelAssigner one labelled grasp per seed at its chosen view, only within 5 mm of a label point (EconomicGrasp, FineGrasp); brings the dataset section compact_labels compact refused / runs (shipped) / runs (shipped) / refused / refused SWADHead and OperationHead are supervised with dense labels
    scale-balanced ScaleBalancedAssigner the matching of GraspNet-baseline plus a loss weight per seed, larger for rare grasp widths; brings the dataset section scale_statistic dense refused / refused / refused / runs / runs (shipped) its seed weights are applied by ObjectnessViewStage and OperationHead only; the others would ignore them silently 
    grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
    --set assigner=scale-balanced -o baseline_scale-balanced.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set assigner=nearest-label-object-seeds -o gsnet_object-seeds.yaml
grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e \
    --set assigner=compact-label          # what the method ships; composes to the same config
grasppanda compose --show assigner=scale-balanced   # the preset with what must be re-tuned

    scale-balanced needs the width histogram (grasppanda prepare graspnet1b --scale-statistic; configs/scale_balanced_grasp/README.md), and a probe of it needs the reference's file (see the slot index). A refusal names the head or the label set that does not fit and, where another shipped config serves it, that config.

    4. How to use each option¶

    One loss term¶

    grasppanda compose --list loss                    # the presets, one line each
grasppanda compose --show loss=quality-focal      # one preset with its notes
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set head.score_loss=quality-focal --set proposal.objectness_loss=focal -o gsnet_focal.yaml
grasppanda probe gsnet_focal.yaml                 # a few iterations on real frames, about a minute
grasppanda train gsnet_focal.yaml

    The left side of --set is <slot>.<loss option> from the table of section 2; the right side is a preset or a component type (--set head.width_loss=Huber, built with its defaults). A preset carries no weight: compose keeps the weight of the loss it replaces and says so. Real output of the command above:

  • proposal.objectness_loss: preset `focal` (FocalLoss) in place of CrossEntropy. Sigmoid focal
    loss (RetinaNet) through torchvision: cross-entropy that turns down elements the network already
    gets right. The weight 1.0 of the replaced loss is kept.

    and the lines it writes into the composed config:

    model:
  proposal:
    objectness_loss:
      type: FocalLoss
      alpha: 0.25                 # positives x alpha, negatives x (1 - alpha); -1: off
      gamma: 2.0                  # exponent of (1 - p_t)
      weight: 1.0                 # kept from the CrossEntropy it replaces; the penalties differ in scale: re-tune
  head:
    score_loss:
      type: QualityFocal
      beta: 2.0                   # exponent of |target - sigmoid(prediction)|
      weight: 15.0                # kept from the SmoothL1 it replaces; the penalties differ in scale: re-tune

    The same by hand, in your own config or on any command line that takes --opts:

    grasppanda train gsnet/gsnet_sunet14_g1b-realsense_10e \
    --opts model.proposal.objectness_loss.type=FocalLoss

    An override of type alone keeps the other keys of the node, so it works only when the new loss has the options of the old one (here: weight). Otherwise replace the whole node in a YAML file.

    Libraries: pip install -e ".[torchvision]" for focal, pip install -e ".[kornia]" for softmax-focal, dice, lovasz-softmax, charbonnier, cauchy and the head preset economic-focal. Without the library the config still loads; building the model raises an error that names the extra.

    Choosing a loss for a term¶

    • Objectness (class, two classes, many easy points): focal (try alpha: -1 first: table-top objectness is far less imbalanced than detection anchors), softmax-focal, class-balanced, ohem, or the set losses dice and lovasz-softmax.
    • Angle, depth and quality classes (class, classes exclude each other): softmax-focal, label-smoothing, poly1, class-balanced, ohem.
    • Graspness, view scores, the SWAD score grid (unit): quality-focal, varifocal, ghm-c, bce train a logit; balanced-l1, huber, ghm-r, charbonnier, cauchy, ohem-smooth-l1 keep the output a value.
    • Widths, tolerances, the scores of OperationHead (value): huber, balanced-l1, ghm-r, charbonnier, cauchy, ohem-smooth-l1. Set the knee (delta, beta, mu) in the units of the target: SWAD and Economic widths are metres x 10.
    • A width as a distribution (bins): distribution-focal, with the head preset decoupled-grid-bins.

    Wrappers: mining, class balance, multi-task weighting¶

    TopK, ClassBalanced and UncertaintyWeighted take another loss as loss:.

    model:
  proposal:
    objectness_loss:
      type: TopK
      fraction: 0.25              # share of the supervised elements that is kept
      loss: {type: FocalLoss, weight: 1.0, alpha: -1, gamma: 2.0}

    uncertainty-weighting is a preset without a loss of its own: compose wraps the loss that is in the term, with its weight. Set it on every term that should take part in the balance:

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set proposal.objectness_loss=uncertainty-weighting \
    --set proposal.graspness_loss=uncertainty-weighting --set view.loss=uncertainty-weighting \
    --set head.score_loss=uncertainty-weighting --set head.width_loss=uncertainty-weighting

      head:
    score_loss:
      type: UncertaintyWeighted
      initial_log_variance: -0.6931   # -ln 2: the factor starts at 1
      loss:
        type: SmoothL1
        weight: 15.0
        beta: 1.0

    A term that is not wrapped keeps its fixed weight. The learned value is the parameter <stage>.<term>.log_variance of the checkpoint. The log-variances are model parameters: an optimizer that decays all parameters pulls them towards 0, so exclude them from weight decay. Wrapped terms, and so the total loss, can become negative.

    A head bundle¶

    grasppanda compose --list head
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set head=swad-focal -o gsnet_swad-focal.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set head=decoupled-grid-bins -o gsnet_grid-bins.yaml
grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e --set head=economic-focal -o eg_focal.yaml

    DecoupledGridHead in a config, with the options that matter:

    model:
  head:
    type: DecoupledGridHead
    num_angle: 12
    num_depth: 4
    depth_step: 0.01
    depth: class                  # class | regression (a continuous depth between the bins)
    width: bins                   # regression | class (bin centre) | bins (expectation)
    width_bins: 16                # for class and bins: 16 over 0.1 m is a bin every 6.7 mm
    score_target: log_friction_fixed_range
    friction_range: [0.1, 1.0]    # the range of the GraspNet-1Billion labels
    score_loss: {type: SmoothL1, weight: 15.0, beta: 1.0}
    angle_loss: {type: CrossEntropy, weight: 1.0}
    depth_loss: {type: CrossEntropy, weight: 1.0}
    width_loss: {type: DistributionFocal, weight: 1.0}
    • Classification or regression of depth and width is the pair of options depth and width; the presets decoupled-grid-class and decoupled-grid-regression are the two ends. The kind of depth_loss and width_loss follows the option, so a loss must be changed with it (the presets do).
    • The class terms are cross-entropies of order ln 12 and ln 4 at the start, the regressed width a distance in metres x 10: watch loss/angle and loss/depth beside loss/score and re-tune the weights. The weights of the presets are starting points.
    • width_decode_gain: 1.2 opens the gripper 20 % wider than learned, as the other bundles of the family do; 1.0 decodes what was learned.
    • A loss and a head combine: --set head=decoupled-grid --set head.score_loss=varifocal.

    5. Pitfalls¶

    • A loss in the wrong kind of term is refused, with the alternatives. Real output of grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set head.width_loss=focal:
    ✗ assigner · head: SWADHead.width_loss is a `value` term (a prediction and a target of equal
  shape, the target an unbounded quantity), but FocalLoss fits `class` or `unit` terms. Losses for
  a `value` term: BalancedL1, GHMR, Huber, L1, MSE, RobustLoss, SmoothL1, TopK,
  UncertaintyWeighted.
    • The scores of the GraspNet-baseline family are not qualities in [0, 1]. The score and view targets of OperationHead and ObjectnessViewStage are log-friction scores up to ln 10, so they are value terms and the sigmoid losses are refused there (OperationHead.score_loss is avalueterm ..., but QualityFocal fitsunitterms).
    • A logit loss changes what the raw output is. After quality-focal, varifocal, ghm-c, focal or bce in a unit term, the stage output is a logit. The shipped stages read it through the sigmoid; a score threshold fitted on the unbounded score of swad does not carry over to swad-focal, whose score lies in [0, 1].
    • Weights are kept, scales are not. A focal term is much smaller than the Smooth-L1 or cross-entropy it replaces, a distribution focal term much larger than a regressed width. Compare the logged loss/... values of both runs before trusting a weight.
    • Set losses cannot weight seeds. dice and lovasz-softmax are refused in the terms of Scale-Balanced-Grasp that receive the per-seed weights of its assigner; the message names the losses that can.
    • Label smoothing and the extra class of EconomicHead. With unmatched_class: true every classifier has one never-supervised output; smoothing gives it target mass. Use decode_argmax: supervised (as economic-focal does) or unmatched_class: false.
    • SWADHead with score_target: log_friction_batch_norm (the GSNet reference behaviour) normalises targets with the extrema of the batch; for a focal-type score loss log_friction_fixed_range gives a target that means the same in every batch (swad-focal sets it).
    • GHM with momentum > 0 keeps running counts as a buffer of the module; it is saved with the checkpoint.
    • Adding a constructor option to a loss used by the shipped configs changes the config hash of every method, and with it every measured record. Label smoothing and class weights are therefore a class of their own (LabelSmoothingCrossEntropy), and CrossEntropy keeps its constructor.
    • Head presets do not cross label formats. --set head=decoupled-grid under EconomicGrasp:
    ✗ assigner · head: CompactLabelAssigner returns 'compact' matched labels, but DecoupledGridHead is
  supervised with 'dense' ones. A head bundle and the assigner that feeds it must agree on the
  label set; the dataset must serve that label set too.

    6. Not wrapped¶

    Looked at for this slot and left out. Licences are what the repository states (licence file, or the repository metadata where no file was found).

    Candidate Why not (yet)
    The grasp head of luyh20/FGC-GraspNet as code no licence file in the repository (its metadata says MIT), and it derives from graspnet-baseline, whose licence is non-commercial research only. The idea (separate outputs) is what DecoupledGridHead implements, without upstream code.
    Heads and losses of graspnet/graspnet-baseline and its descendants as code non-commercial research licence. The ported methods are written here from papers and behaviour.
    NVlabs/contact_graspnet (per-point contact head with width bins) its License.pdf is the NVIDIA Source Code License for Contact-GraspNet (non-commercial; see View, section 6); not copied. Its top-k selection of point errors is the idea behind TopK.
    sh8/ZeroGrasp CC BY-NC 4.0.
    Gradient surgery between loss terms (PCGrad: WeiChengTseng/Pytorch-PCGrad, BSD-3-Clause; Jacobian descent: TorchJD/torchjd, MIT) they need one backward pass per loss term inside the training step; a loss primitive only returns a value. A trainer hook, not an option of this slot. Of the multi-task weightings only the one that is a function of the loss values (uncertainty weighting) is wrapped.
    Ranking losses (allegro/allRank, Apache-2.0; teddykoker/torchsort, Apache-2.0) a loss over the order of the grasps of a scene needs the frame boundaries, which a primitive does not see; torchsort has a compiled extension. Not started.
    Ordinal regression of the quality classes (Raschka-research-group/coral-pytorch, MIT) needs another output layer (one logit per threshold) in EconomicHead, i.e. a new term kind and a head option. Not started.
    Label and feature distribution smoothing for imbalanced regression (YyzHarry/imbalanced-regression, MIT) needs the label statistics of the training set per term. Not started.
    Rotated-box losses of open-mmlab/mmrotate (Apache-2.0) they compare oriented boxes in the image plane; no seed-based stage predicts one.
    A decoupled head for depth-axis crops or for compact labels DecoupledGridHead reads dense label grids and crops without a depth axis only, so it is refused under four of the five methods as shipped.
    Per-seed weights in SWADHead, EconomicHead, DecoupledGridHead applies_seed_weights is false for the three; only OperationHead and ObjectnessViewStage honour the weights of ScaleBalancedAssigner.
    Loss slots for HGGD its loss terms are functions inside the detector, not config nodes.
