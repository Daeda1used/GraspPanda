    Grouper: what is gathered around a seed and how it becomes the feature the head reads¶

    Words such as seed, contract, preset, adapter, label set and point painting are explained in the slot index.

    Which of these options fit a method

    Every method has a page that lists the options of each of its slots with what was measured for each (the verdict, the levels composes, runs, learns and predicts, the class, the grasps, the reason of a refusal): GSNet (grouper); EconomicGrasp (grouper); FineGrasp (grouper); GraspNet-baseline (grouper); Scale-Balanced-Grasp (grouper). In a terminal: grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list grouper.

    Class: one run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. Where this page names a class or a measured verdict, it is one of the measured classes.

    1. The task of the slot¶

    A seed-based detector (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp) first picks about a thousand seeds on the scene and one approach direction per seed. The grouper then looks at the neighbourhood of every seed in the frame of that approach direction and turns it into one feature vector (or one per insertion depth). The head bundle predicts in-plane angle, depth, width and score from that feature and nothing else, so the grouper decides what the head can know about the local shape.

    Position in the pipeline: backbone → proposal → view → (assigner) → grouper → head.

    Every published crop is the same five steps, and almost every alternative replaces exactly one of them:

    step what the ported methods do what this page adds
    query: which points, in which shape a cylinder along the approach axis ball, k nearest, oriented box, grid of balls, grid of cells
    geometry of a neighbour offset in the crop frame the same with its length
    encoder per neighbour shared MLP (plus self-attention in EconomicGrasp) DGCNN edge feature, PointNeXt InvResMLP, layers of PyTorch Geometric
    pooling maximum mean, attentive pooling, vector attention, all with a padding mask
    fusion, residual attention over radii (FineGrasp), linear + gate (Scale-Balanced-Grasp) linear / max / mean over radii (MultiRadiusGroup), projected seed residual

    No AP is claimed for any option on this page. Each was built, trained for 20 iterations on 8 real frames and asked to predict (grasppanda probe); that shows it is usable, not that it is good.

    2. Input and output¶

    class Grouper(nn.Module):
    support: ClassVar[Literal["seeds", "scene"]]   # which points are grouped
    out_axes: ClassVar[tuple[str, ...]]            # ("seed", "channel") or ("seed", "depth", "channel")
    out_channels: int                              # width of the returned feature
    uses_seed_features: bool = False               # forward takes the seed features as 4th argument

    def forward(self, support: PointFeatures, centres: Tensor, rotation: Tensor
                [, seed_feats: Tensor]) -> GroupFeatures: ...
    support PointFeatures: points (N, 3) in metres, camera frame, with batch offsets, and features (N, C). With support = "seeds" these are the M seeds of the batch with the encoder's features (C = in_channels, the width of the scene encoder, injected by the detector). With support = "scene" it is the whole scene cloud (20 000 points per frame in the shipped recipes): with features under a dense encoder, with zero feature channels under a sub-sampling encoder.
    centres (M, 3) crop centre per seed, metres, camera frame. At inference the seed itself; in training the centre the assigner chose (the matched label point for some methods), so a crop may contain no point at all.
    rotation (M, 3, 3) crop frame per seed. Column 0 is the approach axis; the head counts in-plane angles about it from column 1. In training the frame comes from the labels and may be a reflection: a grouper must not assume a right-handed frame. A neighbour p sits at Rᵀ (p − c) in the crop frame.
    seed_feats (M, C) features of the seeds; passed only when the grouper sets uses_seed_features.
    returns GroupFeatures(feats, axes): (M, out_channels) with axes ("seed", "channel"), or (M, D, out_channels) with ("seed", "depth", "channel"), one row per seed in the order given.

    All seeds of a batch are flattened: M = batch × seeds per frame, every frame has the same number of seeds, and a crop never sees points of another frame.

    What the neighbours require, and what the config checker does with the contract attributes (stage_contract_problems in grasppanda/models/detectors/seed_based.py):

    • out_axes must equal the head's in_axes. SWADHead (GSNet) and EconomicHead (EconomicGrasp, FineGrasp) read ("seed", "channel"); OperationHead (GraspNet-baseline, Scale-Balanced-Grasp) reads ("seed", "depth", "channel"). An axis is never added or squeezed implicitly; the two adapters of section 4.6 do it explicitly.
    • The depth axis has one entry per depth bin of the head: the length of the grouper's hmax list, or its num_depth, must equal head.num_depth.
    • out_channels is handed to the head as its in_channels; nothing to configure.
    • The width of the seed features (new, see section 5): a grouper that adds the seed features to its crops states the width it needs (required_seed_channels), and the check compares it with what the encoder returns.
    • support must be seeds or scene. A scene-support grouper works under both kinds of encoder; whether it reads scene features is its own option.

    Conventions of the queries (grasppanda.ops.ball_query, box_query, cylinder_query, knn): the first nsample hits in index order; missing slots repeat the first hit; a query without any hit returns point 0 of its frame. A maximum does not notice the copies; a mean or an attention does, which is why the groupers below mask them.

    3. Options at a glance¶

    "Name" is what you write after --set grouper=; "class" is what you write as type:. Route: own = written here on grasppanda.ops from the paper (a few lines per part), A = adapted source, L = bridge to a library. All weights are random init: no released checkpoint contains any of these crops for grasping. Venues are those of the arXiv record or the proceedings page, opened on 2026-10-13.

    4. How to use each option¶

    One command composes a child config of a method with the grouper replaced, checks it, and says what it did; one more probes it on real frames:

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=roi-grid -o my.yaml
grasppanda probe my.yaml --iters 20 --frames 8
grasppanda train my.yaml

    slot      component             from
────────  ────────────────────  ─────────────────
backbone  SparseUNet14          base config
proposal  GraspnessFPS          base config
view      TemplateViewStage     base config
assigner  NearestLabelAssigner  base config
grouper   RoIGridGroup          preset `roi-grid`
head      SWADHead              base config

contracts
  ✓ backbone · proposal
  ✓ backbone · grouper
  ...
  ✓ grouper · head

config check
  ✓ valid  (hash d99e1d7a282f)

    An option of the grouper is changed on the same command line (--opts model.grouper.nsample=32) or in the file. Every preset is a file under grasppanda/presets/grouper/ whose header says what must be re-tuned. There are no pretrained weights to load for any grouper. To start the other stages from a checkpoint of the method with its own grouper, the options are runtime.load_from=<file> with runtime.allow_weight_mismatch=true (the keys that did not match are printed); this was not run for this page.

    4.1 LocalGroup: shape, encoder and pooling as options¶

    model:
  grouper:
    type: LocalGroup
    shape: cylinder          # ball | knn | box | cylinder
    radius: 0.05             # ball / cylinder radius, half side of the box section (m)
    hmin: -0.02              # box and cylinder: near and far end along the approach axis (m)
    hmax: 0.04
    nsample: 16              # neighbours per crop (k of knn)
    padding: first           # first: repeat the first member, masked | cyclic: repeat in turn
    geometry: offset         # offset | offset+distance
    encoder: mlp             # mlp | edge | invres
    pool: max                # max | mean | attentive | vector_attention
    mlp_channels: [256, 256] # the last width goes to the head

    All 48 combinations of shape × encoder × pool are legal and unit-tested. How to choose:

    • shape: cylinder is what every grasp method uses (long along the approach axis). ball has no preferred axis. box is the cylinder with a square section, the shape of detection RoIs. knn has no radius: the reach follows the seed density, which helps on sparse regions and hurts when the 16 nearest seeds are all on the table.
    • encoder: edge tells the MLP how a neighbour differs from the seed (DOGraspNet reports this offset-driven aggregation for grasping; its code is non-commercial and was not used). invres adds capacity after the pooling and a residual path from the seed.
    • pool: max is robust to padding. mean, attentive and vector_attention use the padding mask. vector_attention is the only pooling that reads the seed's own feature.
    • The crop gathers among the seeds (1024 per frame): sizes and nsample belong to the seed density of the proposal as much as to the objects.

    4.2 DepthLocalGroup: the same, over the scene, one feature per depth bin¶

    model:
  grouper:
    type: DepthLocalGroup
    shape: ball                        # ball | knn | box | cylinder
    radius: 0.05
    hmin: -0.02
    hmax: [0.01, 0.02, 0.03, 0.04]     # one far end per depth bin of the head
    nsample: 64
    pool: max                          # max | mean | attentive
    mlp_channels: [64, 128, 256]
    seed_residual: none                # none | projected (adds W·f of the seed feature)

    The crop is gathered once, to the farthest reach, and bin d pools the members with hmin < x < hmax[d]. This differs from DepthCylinderGroup, which queries nsample points per depth: here the near bins hold fewer members than nsample. seed_residual: projected works with any encoder width; the gated residual of Scale-Balanced-Grasp does not (section 5).

    4.3 RoI pooling of 3-D detectors: RoIGridGroup, RoIAwareGroup, VoxelSetAbstractionGroup¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=roi-grid
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=roi-aware
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=voxel-set-abstraction

    model:
  grouper:
    type: RoIGridGroup
    radius: 0.05          # the box: 2 * radius across the approach axis,
    hmin: -0.02           # hmin .. hmax along it
    hmax: 0.04
    grid_size: 3          # 27 grid points
    pool_radius: 0.03     # ball around every grid point; >= box side / grid_size
    nsample: 8
    mlp_channels: [64, 64]
    fc_channels: [256, 256]

    The region of a detection RoI is a box with a yaw angle; here it is the box of a seed in its approach frame. Unlike a max over the crop, both RoI poolings keep where in the box a feature was found. roi-aware leaves empty cells at zero, so with 1024 seeds per frame most of its 64 cells are empty: try grid_size: 2 or 3. voxel-set-abstraction is the one option that reads the scene and returns (seed, channel); scene_features: true adds the dense features of the scene points and needs a dense encoder (otherwise the grouper stops with a message that says so).

    4.4 PyGConvGroup: layers of PyTorch Geometric¶

    pip install -e ".[torch_geometric]"        # torch_geometric, a pure Python wheel
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=pyg-gatv2-conv \
    --opts 'model.grouper.conv_args={heads: 8}'

    model:
  grouper:
    type: PyGConvGroup
    conv: PointTransformerConv   # PointNetConv | PointTransformerConv | EdgeConv | GATv2Conv | TransformerConv
    conv_args: {}                # further keyword arguments of the layer
    shape: cylinder              # the same shapes as LocalGroup
    radius: 0.05
    hmin: -0.02
    hmax: 0.04
    nsample: 16
    out_channels: 256

    The crop is handed to the layer as a bipartite graph in the crop frame: every member is a source node at its offset Rᵀ (p − c) / radius, the seed is the target node at the origin. Nothing is padded: a crop with five members has five edges. The five layers above are the ones that were run; adding another needs three lines in PYG_CONVS (grasppanda/models/groupers/pyg.py).

    4.5 Several radii: MultiRadiusGroup (linear, max, mean) and MultiScaleGroup (attention)¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=multi-scale-linear

    model:
  grouper:
    type: MultiRadiusGroup
    radius: 0.07                       # largest crop
    radius_scales: [0.25, 0.5, 0.75, 1.0]
    fusion: linear                     # linear | max | mean
    branch:                            # one copy per radius; its radius is set above
      type: CylinderGroup
      nsample: 16
      mlp_channels: [256, 256]

    branch is any seeds-support grouper with a radius, LocalGroup and PyGConvGroup included. MultiScaleGroup (preset multi-scale) is the same with FineGrasp's attention over the scales.

    4.6 The other family's crops: depth-embed and depth-pool¶

    # a (seed, channel) crop under GraspNet-baseline or Scale-Balanced-Grasp
grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
    --set grouper=depth-embed
# a depth-sliced scene crop under GSNet, EconomicGrasp or FineGrasp
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set grouper=depth-pool

    model:
  grouper:
    type: DepthEmbedGroup
    num_depth: 4                 # = model.head.num_depth
    grouper: {type: RoIGridGroup}   # any seeds-support (seed, channel) grouper

    depth-embed computes the crop once and tells the depth bins apart only by a learned embedding, which is weaker than a crop per depth; depth-pool throws the depth resolution away. They exist so that a swap is possible, not because a paper proposes them.

    5. The width of the seed features¶

    Scale-Balanced-Grasp's crop adds sigmoid(W f) · f of the seed feature f to its 256-channel crop features, so the encoder had to return 256 channels. An encoder with an out_channels option was fitted by compose; one without (LitePT, PTv3 and its pretrained variants, PointNeXt, PointNet2Dense) passed the config check and failed when the model was built. Now:

    • DepthCylinderGroup.required_seed_channels(options) states the width, and the config check compares it with the width the encoder declares for its options (Backbone.output_channels; an encoder whose width is known only once built, such as Uni3D without out_channels, is built once for the check, without released weights). grasppanda compose ... --set backbone=PointNeXt --no-adapter under Scale-Balanced-Grasp now ends with:
    ✗ backbone · grouper: DepthCylinderGroup as configured adds the seed features to its
  256-channel crop features, but PointNeXt returns 32-channel features. Use
  `type: DepthCylinderProjectionGroup` for the grouper (the same crop with a linear layer
  in front of the residual; `grasppanda compose` does that), or give the encoder 256
  output channels where it has that option, or end the grouper's `mlp_channels` on 32, or
  set `seed_residual: none`.
    • DepthCylinderProjectionGroup is the same crop with a linear layer in_channels → out_channels in front of the gate. Without --no-adapter, compose puts it in place of DepthCylinderGroup, with the options of the crop it replaces, and says so:
    grouper   DepthCylinderProjectionGroup         base config, projected
...
• grouper: DepthCylinderProjectionGroup in place of DepthCylinderGroup. DepthCylinderGroup as
  configured adds the seed features to its 256-channel crop features, but FurthestPointSubsample
  returns 32-channel features. DepthCylinderProjectionGroup is the same crop with a linear layer
  in front of its seed residual; it changes the model (the base method has none). `--no-adapter`
  leaves the pair refused.

    The reference model has no such layer, so the composed model is a variant of Scale-Balanced-Grasp, not the paper's.

    • The fix is a class of its own, not an option of DepthCylinderGroup, on purpose: the config hash of a shipped config covers the constructor defaults of its components, so a new option on a ported class would change the hash of every config that uses it (and orphan their measured records and checkpoints). The same holds for MultiRadiusGroup beside MultiScaleGroup.

    The same holds for every encoder preset without a 256-channel output, including those that start from released weights (the check learns the width from the architecture, so its verdict does not depend on which weight files are on the machine). The encoder cells under Scale-Balanced-Grasp that used to fail at build were probed again; in each, compose put DepthCylinderProjectionGroup in place of DepthCylinderGroup:

    6. Pitfalls met while building this¶

    • Padding and non-max pooling. The queries repeat the first hit in empty slots. With a mean or an attention those copies would outvote the real members; LocalGroup, DepthLocalGroup and VoxelSetAbstractionGroup mask them, and PyGConvGroup does not create them. If you write a pooling of your own, use the mask crop_members returns.
    • Empty crops in training. The crop centre comes from the assigner and need not be a seed, so a seed-support box or cylinder may be empty. The queries then return point 0 of the frame; here its first slot counts as the only member, so no pooling reduces an empty set (a soft-max over nothing is NaN).
    • Do not add an option to a component that shipped configs use. The first version of this work added fusion to MultiScaleGroup and seed_projection to DepthCylinderGroup; 130 measured cells stopped matching what compose writes, because the config hash had changed. New behaviour goes into a new class or a subclass.
    • A bridge passes the config check without its library. The check compares contracts and does not build; PyGConvGroup without torch_geometric stops when the model is built, with the pip install line.
    • Scale-Balanced-Grasp needs its width histogram to be probed on real frames (data.train.dataset.scale_statistic); without it grasppanda probe falls back to a synthetic scene and reports wired. tools/probe_grid.py takes --scale-statistic-sha for that.
    • knn over the scene is short-sighted. With 20 000 points the 64 nearest lie within about a centimetre, so the far depth bins of depth-knn see the same members as the near ones. Raise nsample or prefer a radius.
    • Memory. A scene-support crop holds seeds × nsample × width activations per MLP layer (and per depth for DepthCylinderGroup); two probes side by side on a shared GPU can run out of memory where one alone runs.
