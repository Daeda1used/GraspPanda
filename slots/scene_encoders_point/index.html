    Scene encoders: point-based networks¶

    Words such as seed, contract, preset, adapter, label set and point painting are explained in the slot index.

    Which of these options fit a method

    Every method has a page that lists the options of each of its slots with what was measured for each (the verdict, the levels composes, runs, learns and predicts, the class, the grasps, the reason of a refusal): GSNet (scene encoder); EconomicGrasp (scene encoder); FineGrasp (scene encoder); GraspNet-baseline (scene encoder); Scale-Balanced-Grasp (scene encoder). In a terminal: grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list backbone.

    Class: one run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. Where this page names a class or a measured verdict, it is one of the measured classes.

    Options for the slot model.backbone of the seed-based methods that work on the raw point cloud: set abstraction (PointNet++ and its descendants), residual MLPs, graph convolutions, random-sampling networks and point-wise networks on a grid pyramid. Sparse-voxel CNNs and serialised transformers have pages of their own.

    Everything on this page comes from existing code: a library bridge, source adapted from a permissively licensed repository, or released weights for a class that already existed. No grasp AP is claimed for any option here. What was checked is stated per option: the contract on tiny clouds in the unit suite, and grasppanda compose plus grasppanda probe on real GraspNet-1Billion frames under the five seed-based methods.

    1. The task of the slot¶

    The scene encoder is the first learned stage of a seed-based detector (GSNet, EconomicGrasp, FineGrasp, GraspNet-baseline, Scale-Balanced-Grasp). It turns one depth-camera view of a cluttered table, 15 000 to 20 000 points, into a feature vector per point. Everything after it reads those features: the proposal picks seeds from them, the view stage chooses an approach direction per seed, the grouper crops the scene around each seed and adds the seed's feature, and the head predicts the grasp. The encoder decides what a seed "knows" about its surroundings before any crop is taken, so its receptive field and its resolution are what matter for this task.

    depth frame -> points (N, 3) -> [ backbone ] -> proposal -> view -> grouper -> head -> grasps
                                  this slot

    HGGD is a detector family of its own (image encoder plus region network) and has no scene point encoder to replace.

    2. Input and output¶

    class Backbone(nn.Module):                # grasppanda/models/base.py
    output: "dense" | "subsampled"        # where the returned features live
    in_channels: int
    out_channels: int
    def forward(self, points: PointSet, feats: Tensor) -> PointFeatures: ...
    points A PointSet: coords of shape (N, 3), metres, camera frame, all clouds of the batch concatenated, with batch offsets (points.sizes, points.batch_index). Clouds of a batch may differ in size. Point spacing on a table top is about 5 mm.
    feats (N, in_channels). GSNet and EconomicGrasp feed constant ones (point_features: ones, 3 channels); FineGrasp feeds coordinates and normals (6 channels); GraspNet-baseline and Scale-Balanced-Grasp feed nothing (in_channels: 0). With point_features: ones the detector builds ones(N, backbone.in_channels), so any in_channels works.
    result, output = "dense" PointFeatures(feats, points): one row per input point, bound to the same PointSet.
    result, output = "subsampled" PointFeatures(feats, points.subset(index)): features on a child set that records which input rows it holds; every cloud of the batch must yield the same number of rows (the seeds).
    out_channels Read by the detector after the encoder is built and injected into proposal, view stage and grouper as their in_channels.

    What the neighbours require, and what the config checker does with it:

    • GraspnessFPS (GSNet, EconomicGrasp, FineGrasp) scores every scene point, so it requires dense. SubsampledSeeds (GraspNet-baseline, Scale-Balanced-Grasp) takes the encoder's own subsample as seeds, so it requires subsampled.
    • The checker compares backbone.output with proposal.requires and refuses a mismatch. grasppanda compose then inserts the adapter that converts: FeaturePropagation (subsampled to dense, one interpolation level) or FurthestPointSubsample (dense to subsampled, keeps npoint furthest-point samples), and says so in its output.
    • When an encoder has an out_channels option, compose sets it to the width of the encoder it replaces (512 for the sparse U-Net methods, 256 for the PointNet++ ones), so the other stages keep their width. When the width is fixed by the architecture, the other stages are built that wide.
    • The width of the seed features is a contract too. The crop of Scale-Balanced-Grasp adds the seed feature to a 256-channel crop feature (seed_residual: gated). An encoder declares the width it returns (Backbone.output_channels), the grouper the width it needs, and the config check compares the two without building anything. For an encoder of another width compose puts DepthCylinderProjectionGroup in place (the same crop with a linear layer in front of the residual) and says so; --no-adapter leaves the pair refused (Grouper, section 5).
    • No contract checks the unit of length. Every published configuration of these networks is for rooms (first radius 0.1 m, grids from 4 cm). The presets below restate radii and grids for a table top and say what they were derived from; all of them are choices by analogy, not tuned values.

    4. How to use each option¶

    The pattern is the same for all of them:

    grasppanda compose --list backbone                        # what exists
grasppanda compose --show backbone=pointmetabase          # one preset with its notes
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=pointmetabase -o gsnet_pointmetabase.yaml
grasppanda probe gsnet_pointmetabase.yaml                 # trains 20 iterations on 8 frames
grasppanda train gsnet_pointmetabase.yaml

    Real output of the compose step (2026-10-13):

    slot      component             from

    Under a method whose proposal needs the other kind of output, compose adds the adapter and says what it did (grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e --set backbone=randlanet):

    backbone  RandLANet in FurthestPointSubsample  preset `randlanet`, in the adapter FurthestPointSubsample

  • wrapped RandLANet in the adapter FurthestPointSubsample (preset `furthest-point-subsample`):
    SubsampledSeeds requires 'subsampled' scene features, but RandLANet returns 'dense' ones (one
    feature per scene point). An adapter changes the model; its notes below say how.
  • FurthestPointSubsample.npoint: 1024, the number of seeds of the proposal
    (`model.proposal.num_seeds`): the points the adapter keeps are the seeds.

    Options are overridden with --opts model.backbone.<option>=<value>; the path addresses the encoder wherever an adapter put it. In a config written by hand the fragment is the model.backbone node of the preset, for example:

    model:
  backbone:
    type: PointMetaBase
    in_channels: 3        # constant ones
    radius: 0.04

    PointNet++ with multi-scale grouping: pointnet2-msg, pointnet2-msg-dense¶

    grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
    --set backbone=pointnet2-msg -o baseline_msg.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=pointnet2-msg-dense -o gsnet_msg.yaml

    model:
  backbone:
    type: PointNet2MSG
    in_channels: 0
    npoints: [2048, 1024, 512, 256]
    radii: [[0.02, 0.04], [0.05, 0.1], [0.1, 0.2], [0.2, 0.3]]    # one list per level
    nsamples: [[32, 64], [16, 32], [16, 16], [16, 16]]
    • PointNet2MSG is a drop-in for the GraspNet-baseline encoder: the same level sizes, the same 1024 seeds and 256 channels, two balls per level. Use it where the method takes seeds from the encoder; PointNet2MSGDense where the proposal scores every point.
    • radii, nsamples and sa_mlps take one list per level with one entry per scale; a level's width is the sum over its scales. fp_mlps (coarsest first) decides where the output lives: k entries stop k levels above the coarsest.
    • Choosing radii: the larger ball of a level is what a single-scale network would use; the smaller one helps where points are dense (near the camera). Cost grows with the sum of nsamples over the scales.

    PointNeXt sizes: pointnext, pointnext-b, pointnext-l, pointnext-xl¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=pointnext-b -o gsnet_pointnext-b.yaml
    preset blocks width sa_layers / sa_use_res parameters with the official segmentation head
    pointnext (S) 1, 1, 1, 1, 1 32 2 / true 0.792 M
    pointnext-b 1, 2, 3, 2, 2 32 1 / false 3.828 M
    pointnext-l 1, 3, 5, 3, 3 32 1 / false 7.125 M
    pointnext-xl 1, 4, 7, 4, 4 64 1 / false 41.576 M

    The presets set radius: 0.04 (room value: 0.1). Depth costs ball queries: every inverted residual block runs one on the reference operators. Released weights: section 5.

    PointMetaBase and PointVector: pointmetabase[-xl], pointvector[-xl]¶

    grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e \
    --set backbone=pointmetabase-xl -o economicgrasp_pointmetabase-xl.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=pointvector -o gsnet_pointvector.yaml

    model:
  backbone:
    type: PointVector          # or PointMetaBase
    in_channels: 3
    radius: 0.04
    blocks: [1, 4, 7, 4, 4]    # XL; the default 1-3-5-3-3 is L
    width: 64
    • Both take the arguments of PointNeXt (blocks, width, strides, radius, radius_scaling, nsample). PointMetaBase also has expansion (1 as published); PointVector has block_nsample (8, fixed in the official code).
    • PointMetaBase is the cheap one: its blocks share one ball query and one offset embedding per stage. The unit suite pins its size to the published ones (2.738 M for L, 15.284 M for XL, 19.672 M for XXL = blocks: [1, 5, 9, 5, 5], width: 64, with the segmentation head).
    • PointVector here is the scene network of the official code (flag: 1: sum over neighbours, ReLU). The object-classification variants of that code are not built.
    • Output width is width (32 or 64): under Scale-Balanced-Grasp see section 6.

    ASSANet: assanet¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=assanet -o gsnet_assanet.yaml
    • radii, nsamples, mlps: per level and scale, as for multi-scale PointNet++, but the two scales of a level run one after the other. reduction: mean (published), max or sum. fp_mlps lists the propagation widths finest first; the first entry is the output width (the preset uses 256, the published network 64).
    • use_xyz: true (set by the preset) appends the coordinates to the input features. Without it the stem batch-normalises features that are the same on every point (the constant ones GSNet, EconomicGrasp, GraspNet-baseline and Scale-Balanced-Grasp feed), and the normalised value of a constant is zero: the encoder returned zeros and learned nothing, which a 20-iteration probe did not show (the first records of this option were made that way and have been replaced). The class now refuses constant features without use_xyz in training, and the probe reports a part that received no gradient.
    • The unit suite pins the default network to the published size (2.425 M with the segmentation head).

    PointMLP: pointmlp¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=pointmlp -o gsnet_pointmlp.yaml
    • Neighbourhoods are by count (k_neighbors), anchors by ratio (reducers): nothing to convert from rooms to a table top.
    • gmp_dim appends a max-pooled vector of the whole frame to every point (0 turns it off). embed_dim: 32 with res_expansion: 0.25 is the authors' small setting.
    • It reads the coordinates itself as its first three input channels; with FineGrasp it also receives coordinates and normals as features (the official model reads coordinates and normals).

    DeLA: dela¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=dela -o gsnet_dela.yaml

    model:
  backbone:
    type: DeLA
    in_channels: 3
    grid_size: [0.005, 0.01, 0.02, 0.04]   # first entry: the point spacing of the input
    • grid_size[0] is the spacing of the input cloud and sets the unit of the offset encoding; the other entries are the cells the cloud is subsampled to. Keep the factor of 2 between levels of the official pyramid unless you also change k.
    • Level sizes depend on the frame, so DeLA is dense only; under GraspNet-baseline and Scale-Balanced-Grasp compose wraps it in FurthestPointSubsample.
    • Not built: the auxiliary relative-coordinate loss and the stochastic depth of the official recipe (a backbone of this slot returns features only).

    DGCNN: dgcnn, dgcnn-static¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=dgcnn -o gsnet_dgcnn.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=dgcnn-static \
    --opts model.backbone.k=48 -o gsnet_dgcnn-static_k48.yaml
    • k: neighbours per point. dynamic: true rebuilds the graph in feature space for layers 2 and 3 (the paper); false keeps the spatial graph. emb_dims: width of the frame-level max-pooled vector, 0 to leave it out. knn_chunk: queries per block of the neighbour search (memory against speed).
    • coords_as_features: true (default) puts the coordinates in front of the input features. Leave it on with point_features: ones, otherwise the network sees constants only.
    • No subsampling: memory is proportional to N x k. Under FineGrasp the probes peaked at 30 GiB (dgcnn) and 36 GiB (dgcnn-static, k: 32); under GSNet at 8 to 11 GiB.

    RandLA-Net: randlanet¶

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --set backbone=randlanet -o gsnet_randlanet.yaml
    • sub_sampling_ratio and dim_output take one entry per level; num_neighbors is by count. Among the cheapest encoders on this page (3 to 4 GiB in the probes under GSNet, EconomicGrasp and GraspNet-baseline).
    • Sampling is random in training and a fixed permutation in evaluation (seed), so inference is repeatable and a frame gives the same result alone or in a batch.
    • A cloud needs at least num_neighbors x prod(ratios[:-1]) points (1024 at the defaults).

    PyTorch Geometric layers: pyg-pointnet, pyg-edgeconv, pyg-point-transformer, pyg-pointgnn¶

    pip install -e ".[torch_geometric]"
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=pyg-point-transformer -o gsnet_pyg-pt.yaml

    model:
  backbone:
    type: PyGPointEncoder
    in_channels: 3
    conv: point_transformer     # pointnet | edge | point_transformer | pointgnn
    channels: [64, 64, 128]     # one layer per entry
    k: 16
    conv_args: {}               # further arguments of the library layer
    preset conv library layer
    pyg-pointnet pointnet torch_geometric.nn.PointNetConv
    pyg-edgeconv edge torch_geometric.nn.EdgeConv
    pyg-point-transformer point_transformer torch_geometric.nn.PointTransformerConv
    pyg-pointgnn pointgnn torch_geometric.nn.PointGNNConv (all channels equal)

    Only the layers are the library's. The stack around them is not a published network: it is the quickest way to try a message-passing layer in a grasp detector. The graph is built by GraspPanda, so torch_geometric alone is enough (no pyg-lib, torch_cluster). Without the library the class says how to install it:

    The backbone PyGPointEncoder needs 'torch_geometric.nn', which is not installed. Install it with: pip install -e ".[torch_geometric]"

    5. Released weights that fit existing classes¶

    tools/convert_backbone_weights.py cuts the encoder out of a released checkpoint, checks it strictly against the class (every tensor present, right shapes; anything left over must be a part the format is known to carry) and writes a file whose keys start with backbone.. Nothing is downloaded by the tool or by a test.

    Read before you rely on such an initialisation:

    • Radii are not stored in a checkpoint. The VoteNet and CSC networks were trained with room radii (0.2 to 1.2 m). They load under the GraspNet-baseline radii (0.04 to 0.3 m) without complaint; because offsets are divided by the radius, the network then sees a table top enlarged about five times. Whether that helps is untested. Printing the room radii, as the tool does, is the honest default; choosing table-top radii is an experiment.
    • Input channels are part of the weights. PointNeXt checkpoints read colour and a height above the floor (4 channels); VoteNet reads one height channel. A camera-frame table-top cloud has no floor height: define what you feed (zero, or height above the table plane) and keep in_channels as printed.
    • The integration test tests/integration/test_backbone_released_weights.py repeats the strict loading when the files lie in $GRASPPANDA_WEIGHTS/components/released_backbones/, and is skipped otherwise.
    • Some research checkpoints pickle their experiment config next to the weights (the CSC file holds an omegaconf object). The tool reads tensors with PyTorch's restricted loader and replaces every other class the file names by an inert stand-in; nothing of the file is executed.

    6. Pitfalls met while building this page¶

    • The grouper of Scale-Balanced-Grasp wants 256 channels from the encoder. pointnext*, pointmetabase* and pointvector* end on their stem width (32 or 64). When this page was first written such a config passed the check and failed at build; the width is a contract now, and compose puts the projected grouper in place (section 2). The model is then a variant of Scale-Balanced-Grasp, not the paper's. The presets of the encoders whose width is free (assanet, pointnet2-msg-dense, and every class with out_channels) are 256 wide for this reason.
    • Probing Scale-Balanced-Grasp needs its width histogram. Without --opts data.train.dataset.scale_statistic.source=legacy_import data.train.dataset.scale_statistic.reference_sha256=<sha> the probe falls back to a synthetic scene and reports wired, not runs (docs/user_guides/combinations.md, "The width histogram").
    • Constant input features starve encoders that read geometry through features. With point_features: ones, an EdgeConv or a point-wise MLP sees constants. DGCNN, PyGPointEncoder, RandLANet, PointMLP therefore read the coordinates themselves; the set-abstraction encoders get geometry through grouped offsets and do not need it.
    • Absolute coordinates. RandLA-Net's published neighbourhood encoding contains the absolute positions of both points, and DGCNN / PointMLP / the bridge read camera-frame coordinates as features: their features are not translation invariant.
    • Frame-level vectors. dgcnn (emb_dims) and pointmlp (gmp_dim) append a max-pooled vector of the whole frame to every point, so features depend on the workspace crop. Both can be switched off.
    • Padded balls under mean or sum. A ball query pads a sparse ball by repeating its first hit. Under max-pooling that is invisible; assanet (mean) and pointvector (sum) count the repeated point several times, as their upstream code does.
    • torch_geometric 2.8 without pyg-lib. Its knn_graph raises 'knn_graph' requires 'pyg-lib>=0.6.0'; the bridge builds the graph itself.
    • Memory. The last column of the table in section 3 is the peak of the probes. The upper end is always FineGrasp, whose own stages are heavy; there the full-resolution encoders (dgcnn*, pyg-pointgnn) reach 30 to 36 GiB. On a GPU shared with other jobs these probes ran out of memory several times before they went through alone.
