    Scene encoders: point-based networks¶

    Seed-based · 5 methods--set backbone=23 options

    These encoders work on the raw point cloud: set abstraction (PointNet++ and its descendants), residual MLPs, graph convolutions and random sampling. Their radii and neighbour counts set how far a point sees. What all scene encoders share is on the overview.

    Use it¶

    grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e \
    --set backbone=pointnext -o graspnet-baseline_pointnext.yaml
grasppanda compose graspnet_baseline/graspnet-baseline_pointnet2_g1b-realsense_18e --list backbone

    grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e \
    --set backbone=pointnext -o gsnet_pointnext.yaml
grasppanda compose gsnet/gsnet_sunet14_g1b-realsense_10e --list backbone

    grasppanda compose scale_balanced_grasp/sbg_pointnet2-transformer_g1b-realsense_18e \
    --set backbone=pointnext -o scale-balanced-grasp_pointnext.yaml
grasppanda compose scale_balanced_grasp/sbg_pointnet2-transformer_g1b-realsense_18e --list backbone

    grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e \
    --set backbone=pointnext -o economicgrasp_pointnext.yaml
grasppanda compose economicgrasp/economicgrasp_sunet14_g1b-realsense_10e --list backbone

    grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --set backbone=pointnext -o finegrasp_pointnext.yaml
grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e --list backbone

    The first command writes a checked config; the second lists every option of the slot under that method, with what was measured. Then grasppanda probe <file> tries the config on real frames and grasppanda train <file> trains it (Swap a component). Each method page lists the same: GraspNet-baseline · GSNet · Scale-Balanced-Grasp · EconomicGrasp · FineGrasp.

    What the columns say, and who is left out
    • Runs: out of the methods the option is a swap under, those under which its probe trained on real frames without error. A method that ships the option is named own and not counted; a method still undecided is counted and named. Measured on 20 training iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, one run per cell; nothing was measured on GraspClutter6D or on Kinect frames.
    • Trains like shipped: out of the methods under which the swap ran, those under which every comparable loss term ended within the method's tolerance of the component it ships, with nothing rising; a method left out is named with why. Measured on 250 iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, at a constant learning rate (FineGrasp: its own warm-up), beside the method as shipped trained the same way twice.
    • How we measure defines every word of these columns.

    Choosing¶

    • The PointNet++ family of the ported methods: pointnet2 and pointnet2-transformer; -dense propagates features back to every point, -msg uses two balls per level.
    • Modern set abstraction: pointnext in four sizes, pointmetabase (one ball query per stage, the cheapest of them) and pointvector.
    • Full resolution, no sub-sampling: dgcnn and the pyg-* layers; memory grows with the number of points times the neighbours.
    • Cheap sampling: randlanet samples at random and pools attentively.
    • Radii are set for a table top by analogy. The published configurations are for rooms (first radius 0.1 m); sweep the radius before comparing encoders.

    Details¶

    The settings that matter, encoder by encoder

    Options are changed with --opts model.backbone.<option>=<value>; the path addresses the encoder wherever an adapter put it.

    PointNet++ with multi-scale grouping (pointnet2-msg, pointnet2-msg-dense):

    model:
  backbone:
    type: PointNet2MSG
    in_channels: 0
    npoints: [2048, 1024, 512, 256]
    radii: [[0.02, 0.04], [0.05, 0.1], [0.1, 0.2], [0.2, 0.3]]    # one list per level
    nsamples: [[32, 64], [16, 32], [16, 16], [16, 16]]

    PointNet2MSG keeps the level sizes of GraspNet-baseline (1024 seeds, 256 channels) with two balls per level; the larger ball is what a single-scale network would use, the smaller helps where points are dense. Cost grows with the sum of nsamples over the scales.

    PointNeXt sizes:

    Preset blocks width sa_layers / sa_use_res Parameters with the official segmentation head
    pointnext (S) 1, 1, 1, 1, 1 32 2 / true 0.792 M
    pointnext-b 1, 2, 3, 2, 2 32 1 / false 3.828 M
    pointnext-l 1, 3, 5, 3, 3 32 1 / false 7.125 M
    pointnext-xl 1, 4, 7, 4, 4 64 1 / false 41.576 M

    The presets set radius: 0.04 (the room value is 0.1). Every inverted residual block runs one ball query.

    PointMetaBase and PointVector take the arguments of PointNeXt (blocks, width, strides, radius, nsample). PointMetaBase shares one ball query and one offset embedding per stage; the unit suite pins its sizes to the published ones. PointVector is the scene network of the official code. Their output width is width (32 or 64).

    ASSANet: use_xyz: true (set by the preset) appends the coordinates to the input features. Without it, constant input features are normalised to zero and the encoder learns nothing; the class refuses that combination in training.

    PointMLP: neighbourhoods by count, anchors by ratio, so nothing to convert from rooms. gmp_dim appends a max-pooled vector of the whole frame to every point (0 turns it off).

    DeLA: grid_size[0] is the spacing of the input cloud and sets the unit of the offset encoding; keep the factor of 2 between levels unless you also change k. Level sizes depend on the frame, so DeLA is dense only.

    DGCNN: k neighbours per point; dynamic: true rebuilds the graph in feature space (the paper), false keeps it spatial; emb_dims is the width of the frame-level vector (0 leaves it out). Keep coords_as_features: true with constant input features.

    RandLA-Net: sub_sampling_ratio and dim_output per level. Sampling is random in training and a fixed permutation in evaluation, so inference is repeatable. A cloud needs at least num_neighbors × prod(ratios[:-1]) points.

    PyTorch Geometric layers (extra torch_geometric): a stack of one library convolution at full resolution; only the layers are the library's, the stack is not a published network.

    Preset conv Library layer
    pyg-pointnet pointnet torch_geometric.nn.PointNetConv
    pyg-edgeconv edge torch_geometric.nn.EdgeConv
    pyg-point-transformer point_transformer torch_geometric.nn.PointTransformerConv
    pyg-pointgnn pointgnn torch_geometric.nn.PointGNNConv (all channels equal)

    The checksums are those of the files as downloaded on 2026-10-13; the full digests are in tests/integration/test_backbone_released_weights.py, which checks them before it loads a file.

    python -m tools.convert_backbone_weights --list
python -m tools.convert_backbone_weights partition8_4096_15k_pointnet.pth csc_pointnet2.pth \
    --format csc-pointnet2
grasppanda train <method config> \
    --opts runtime.load_from=csc_pointnet2.pth runtime.allow_weight_mismatch=true
    • Radii are not stored in a checkpoint. These networks were trained with room radii; they load under table-top radii without complaint, and then see the table enlarged about five times. Whether that helps is untested.
    • Input channels are part of the weights. PointNeXt reads colour and a height above the floor, VoteNet one height channel; a camera-frame table-top cloud has no floor height, so define what you feed.
    • The dataset terms of S3DIS, SUN RGB-D and ScanNet apply; treat the files as research-only until you have checked. The files were loaded strictly once; activations were not compared with the upstream code.
    Pitfalls met while building this
    • The grouper of Scale-Balanced-Grasp wants 256 channels. pointnext*, pointmetabase* and pointvector* end on 32 or 64; compose puts the projected grouper in place, and the model is then a variant of Scale-Balanced-Grasp. The encoders whose width is free are set 256 wide by their presets for this reason.
    • Constant input features starve encoders that read geometry through features. DGCNN, PyGPointEncoder, RandLANet and PointMLP therefore read the coordinates themselves.
    • Absolute coordinates. RandLA-Net's neighbourhood encoding, DGCNN, PointMLP and the bridge read camera-frame coordinates as features, so their features are not translation invariant.
    • Frame-level vectors. dgcnn (emb_dims) and pointmlp (gmp_dim) append a vector of the whole frame to every point, so features depend on the workspace crop; both can be switched off.
    • Padded balls under mean or sum. A ball query pads a sparse ball by repeating its first hit; assanet (mean) and pointvector (sum) count it several times, as upstream does.
    • torch_geometric without pyg-lib cannot build a k-NN graph; the bridge builds it itself.
    Not wrapped
    Candidate Why not
    KPConv (rigid and deformable) needs kernel-point dispositions, radius neighbourhoods and a grid pyramid computed in its own data pipeline with compiled code; a follow-up of its own.
    KPConvX / KPConvD expected to need the same; not attempted.
    RandLA-Net, authors' repository CC BY-NC-SA 4.0; the MIT implementation of Open3D-ML was adapted instead.
    Contact-GraspNet's PointNet++ layout and weights a non-commercial licence; its three-scale layout can be written as a PointNet2MSG config by hand.
    XConv (PointCNN), GravNetConv of PyTorch Geometric they build their graph inside the layer, which needs pyg-lib.
    DeepLA-Net, LinNet, PointMixer, SPoTr, X-3D, PAConv, RepSurf, PVCNN, DeepGCN not reached, or no licence file found earlier.
