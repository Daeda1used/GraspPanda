    HGGD¶

    Run HGGD in five minutes from the authors' checkpoint: the weights, a first picture, the same from Python and in the browser, a first number on the benchmark. Then the options of every slot: what fits where HGGD ships its components, and what was measured for each.

    Run HGGD in five minutes¶

    From the authors' checkpoint to grasps on a scene: on the command line, from Python or in a browser, then a first number on a part of the benchmark. Every command here is run by the test suite (by parsing it, on a toy detector, or on the files it needs); what each printed when it was measured is said under it, with the date, the commit and the machine. The numbers come from the method's metafile and five_minutes.json.

    1. The weights¶

    GraspPanda publishes no weights for HGGD: the checkpoint is the authors', under their licence, and weights converted from it are not redistributed by the project. Download the authors' file yourself:

    • File: HGGD_realsense_checkpoint, from https://cloud.tsinghua.edu.cn/d/e3edfc2c8b114513b7eb/
    • Licence: MIT (the upstream repository); trained on GraspNet-1Billion (CC BY-NC-SA 4.0)
    • SHA-256: b95da06d8723298ad28e4c720c3a6a8af73dfe6f2e8126f43de8845bf62ad6df

    Convert it once, from the root of your GraspPanda checkout (the converter is a tool of the repository; it is not installed with the package):

    python -m tools.convert_checkpoint HGGD_realsense_checkpoint hggd_realsense.pth \
    --source-format hggd --camera realsense

    It writes hggd_realsense.pth: every tensor of the authors' file under the name of the module that plays its role here, no value changed, with a note of the file it came from. A tensor left over or missing stops the conversion with a report; nothing is ever loaded partially.

    2. Grasps on the example scene¶

    grasppanda demo hggd/hggd_r34w8_g1b-realsense_15e \
    --weights hggd_realsense.pth --example --collision-filter

    --example is the synthetic table-top scene that ships with GraspPanda: no dataset and no download. The command prints the config and its hash, how the weights loaded (every tensor matched, none missing), the test pipeline, the cloud, how many grasps the model predicted and how many the collision filter left (the config's variant cd: ModelFreeCollisionFilter then GraspNMS), and the ten best grasps. It writes into work_dirs/hggd_r34w8_g1b-realsense_15e/demo/:

    • grasps.npy: the grasps that are left, (G, 17) float32 in the GraspNet layout, best first, camera frame, metres;
    • grasps.png and grasps.gif: the cloud with the 30 best grasps, still and swinging around the scene;
    • example/: the scene as files (depth.png, rgb.png, mask.png, intrinsics.txt).

    Measured with the authors' checkpoint, converted: 14.5 s for the whole command; 25,600 points to the model; 470 grasps predicted, then 287 after ModelFreeCollisionFilter → 72 after GraspNMS (2026-10-15, commit ea6268b, one NVIDIA RTX A6000 shared with other jobs). Run again at commit 0ddca31 (2026-10-15): the same counts, 16.9 s.

    The scene files stand in for a camera. On your own depth image, as on these:

    grasppanda demo hggd/hggd_r34w8_g1b-realsense_15e \
    --weights hggd_realsense.pth \
    --depth work_dirs/hggd_r34w8_g1b-realsense_15e/demo/example/depth.png \
    --intrinsics work_dirs/hggd_r34w8_g1b-realsense_15e/demo/example/intrinsics.txt \
    --rgb work_dirs/hggd_r34w8_g1b-realsense_15e/demo/example/rgb.png \
    --collision-filter --out work_dirs/camera

    HGGD reads the colour image registered to the depth image (--rgb) and crops no workspace. Units and frames, the depth scale and the intrinsics: Your own camera.

    3. The same from Python¶

    from grasppanda import GraspInferencer
from grasppanda.apis import example_scene

scene = example_scene()  # the scene of --example
inferencer = GraspInferencer(
    "hggd/hggd_r34w8_g1b-realsense_15e", "hggd_realsense.pth"
)
grasps = inferencer(
    depth=scene.depth, intrinsics=scene.intrinsics,
    depth_scale=scene.depth_scale, rgb=scene.rgb, collision_filter=True,
)
print(len(grasps), grasps.sort_by_score().to_graspnet_array()[:3])

    It runs the demo's pipeline on the demo's input, so it returns the demo's 72 grasps. Measured: 72 grasps, 8.2 s for the script (2026-10-15, commit 0ddca31, one NVIDIA RTX A6000 shared with other jobs). HGGD reads the colour image (rgb=) and takes no mask. The fields of a grasp and what else the call takes: From Python.

    4. In the browser¶

    # ~/grasppanda_weights: the folder that holds hggd_realsense.pth
grasppanda explore --weights-dir ~/grasppanda_weights

    The page opens at http://127.0.0.1:8765/. In the tab Run a method choose HGGD: hggd_realsense.pth is chosen for you by its name. Keep the example scene (or upload a depth image with its intrinsics), tick the collision filter and press Run: the page shows the picture, the best ten grasps, the counts through the post-processing and the command that does the same in a terminal. The server listens on your machine only, reads weights only from that folder and downloads nothing: Run in the browser.

    5. A first number on the benchmark¶

    With GraspNet-1Billion on disk (export GRASPPANDA_GRASPNET1B_ROOT=..., see Dataset preparation), score the weights on every 64th frame of the seen test scenes, 120 frames:

    grasppanda test hggd/hggd_r34w8_g1b-realsense_15e \
    --weights hggd_realsense.pth \
    --opts data.test.dataset.split=test_seen data.test.dataset.frame_step=64 evaluation.num_workers=4

    It prints AP, AP0.8 and AP0.4 for every variant of the config, raw (the predictions as they are) and cd (with the collision filter), and writes a result record per variant into the run directory under work_dirs/. Testing needs no derived asset; the evaluator extracts a cache from the dataset's object models the first time it runs, which the times below do not include.

    Weights, provenance Collision filter AP, 120 frames of test_seen AP, whole seen split Difference Wall time, commit
    the authors' checkpoint, converted, author-ckpt off 58.16 58.33 (record) −0.17 53 s, ea6268b
    on 64.14 63.70 (record) +0.44

    Provenance: author-ckpt, the authors' weights, evaluated by GraspPanda. Inputs: no input is derived from ground truth (the config crops no workspace). On these 120 frames the AP is within 0.44 AP of the whole split, so the subset tells you quickly whether your installation gives what the records say; it is not a benchmark number. Measured on 2026-10-15 on one NVIDIA RTX A6000 shared with other jobs.

    The machine: one NVIDIA RTX A6000 (48 GB) shared with other jobs, an AMD EPYC 7262 with OMP_NUM_THREADS=3; Python 3.12, PyTorch 2.7.1 with CUDA 11.8, spconv 2.3.8.

    The options of every slot¶

    Every slot of HGGD (hggd/hggd_r34w8_g1b-realsense_15e), what the method ships with there, the options that fit it and the ones that do not, each with what was measured: the cells of the measured grid that replace that one slot of HGGD. The method itself: its README. The same lists, with every message whole, in a terminal or as JSON:

    grasppanda compose hggd/hggd_r34w8_g1b-realsense_15e --list            # every slot
grasppanda compose hggd/hggd_r34w8_g1b-realsense_15e --list <slot> --json

    One run, seed 0, 20 iterations, 8 frames of one scene; a class counts verdicts, not accuracy. No accuracy appears on this page, and none follows from it: a probe trains 20 iterations on 8 frames and shows whether a combination works, not how good it is.

    How to read a row: C R L P are the four levels of the cell under HGGD, composes, runs, learns and predicts (✓ reached, ✗ not, ? undecided: not checked for a record of the first judge, unstable, not repeated for an unstable run nobody probed again). The Class of an option counts the methods under which it reached each level; levels with the same class are named together. A probe that predicted no grasp on any frame is greyed. The levels, the classes and their thresholds are defined on the measured page, Measured classes.

    Slot Written as Shipped Fit Do not fit Not probed
