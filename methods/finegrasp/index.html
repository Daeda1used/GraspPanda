    FineGrasp¶

    Seed-based skeleton arXiv 2025 depth input equal to the reference ✓ authors' weights scored here

    From the point cloud of a depth image and its surface normals, it predicts grasps as EconomicGrasp does, with graspness normalised within every object and crops at four radii fused by attention.

    Paper · Reference code · Configs, results and notes

    Run FineGrasp in five minutes¶

    Four steps from the authors' checkpoint to grasps. A test parses each command and runs the demo and the Python code on a toy detector of the method's family.

    1. Get the weights¶

    GraspPanda publishes no weights for FineGrasp: the file to download is the authors' checkpoint, under its licence. Download finegrasp_pipeline/model.safetensors (Hugging Face) and convert it once, from the root of a GraspPanda checkout:

    python -m tools.convert_checkpoint finegrasp_pipeline/model.safetensors \
    finegrasp_realsense.pth \
    --source-format finegrasp --camera realsense
    Licence, checksum and what the converter writes
    • Licence: apache-2.0 on the model card; trained on GraspNet-1Billion, whose data and labels are CC BY-NC-SA 4.0
    • SHA-256 of the download: 30c1f335567dcd726c11fb60249da65e26cc92c2f82928a4e4123ac235b38f79
    • What the converter writes: finegrasp_realsense.pth, every tensor of the downloaded file under the name of the module that plays its role here, no value changed, with a note of the file it came from. A tensor left over or missing stops the conversion with a report; nothing is ever loaded partially. The converter is a tool of the repository; it is not installed with the package.

    2. Grasps on the example scene¶

    grasppanda demo finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --weights finegrasp_realsense.pth --example --collision-filter

    --example is a synthetic table-top scene shipped with GraspPanda: no dataset, no download. 14.8 s for the whole command, 613 grasps kept (one NVIDIA RTX A6000 shared with other jobs).

    What it prints and writes, and every measured run

    The command prints the config and its hash, how the weights loaded (every tensor matched, none missing), the test pipeline, the cloud, how many grasps the model predicted and how many the collision filter left (the config's variant cd: ModelFreeCollisionFilter), and the ten best grasps. It writes into work_dirs/finegrasp_sunet14_g1b-realsense_10e/demo/:

    • grasps.npy: the grasps that are left, (G, 17) float32 in the GraspNet layout, best first, camera frame, metres;
    • grasps.png and grasps.gif: the cloud with the 30 best grasps, still and swinging around the scene;
    • example/: the scene as files (depth.png, rgb.png, mask.png, intrinsics.txt).

    Measured with the authors' checkpoint, converted: 14.8 s for the whole command; 20,000 points to the model, sampled from 316,254 in the workspace; 1024 grasps predicted, 613 left after ModelFreeCollisionFilter (2026-10-15, commit ea6268b, one NVIDIA RTX A6000 shared with other jobs). Run again at commit 0ddca31 (2026-10-15): the same counts, 15.5 s.

    From Python (step 3): 613 grasps, 11.4 s for the script (2026-10-15, commit 0ddca31, one NVIDIA RTX A6000 shared with other jobs).

    3. From Python, a browser or your camera¶

    from grasppanda import GraspInferencer
from grasppanda.apis import example_scene
scene = example_scene()  # the scene of --example
inferencer = GraspInferencer(
    "finegrasp/finegrasp_sunet14_g1b-realsense_10e", "finegrasp_realsense.pth"
)
grasps = inferencer(
    depth=scene.depth, intrinsics=scene.intrinsics,
    depth_scale=scene.depth_scale, mask=scene.mask,
    table_from_camera=scene.table_from_camera, collision_filter=True,
)
print(len(grasps), grasps.sort_by_score().to_graspnet_array()[:3])

    It runs the demo's pipeline on the demo's scene and returns its 613 grasps. mask= stands in for the segmentation the config crops the workspace with; on your camera, pass a mask or workspace=(xmin, ymin, zmin, xmax, ymax, zmax) in metres. More: From Python.

    # ~/grasppanda_weights: the folder that holds finegrasp_realsense.pth
grasppanda explore --weights-dir ~/grasppanda_weights

    Open http://127.0.0.1:8765/ and choose FineGrasp in the Run tab: finegrasp_realsense.pth is chosen for you by its name. Keep the example scene or upload a depth image with its intrinsics, and press Run: the page shows the picture, the best ten grasps, the counts through the post-processing and the command that does the same in a terminal. The server listens on your machine only and downloads nothing: Run in the browser.

    grasppanda demo finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --weights finegrasp_realsense.pth \
    --depth work_dirs/finegrasp_sunet14_g1b-realsense_10e/demo/example/depth.png \
    --intrinsics work_dirs/finegrasp_sunet14_g1b-realsense_10e/demo/example/intrinsics.txt \
    --workspace -0.25 -0.2 0.35 0.25 0.2 0.8 \
    --collision-filter --out work_dirs/camera

    The scene files of step 2 stand in for a camera. FineGrasp was trained on clouds cropped around the objects; on a camera image, --workspace (a box in the camera frame, metres) or --mask does that crop. Units, frames, the depth scale and the intrinsics: Your own camera.

    4. A first number on the benchmark¶

    With GraspNet-1Billion on disk (Datasets), score every 64th frame of the seen test scenes, 120 frames:

    grasppanda test finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --weights finegrasp_realsense.pth \
    --opts data.test.dataset.split=test_seen data.test.dataset.frame_step=64 \
    evaluation.num_workers=4

    Measured with the authors' checkpoint, converted: AP 71.21 without the collision filter and 72.99 with it, within 0.70 AP of the whole split.

    What it prints, and every measured run against the whole split

    It prints AP, AP0.8 and AP0.4 for every variant of the config, raw (the predictions as they are) and cd (with the collision filter), and writes a result record per variant into the run directory under work_dirs/. Testing needs no derived asset; the evaluator extracts a cache from the dataset's object models the first time it runs, which the times below do not include.

    The machine: one NVIDIA RTX A6000 (48 GB) shared with other jobs, an AMD EPYC 7262 with OMP_NUM_THREADS=3; Python 3.12, PyTorch 2.7.1 with CUDA 11.8, spconv 2.3.8.

    How to swap, and how to read these lists

    Swap one option in with a single line, or list the options of a slot:

    grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e \
    --set <slot>=<option> -o swap.yaml
grasppanda compose finegrasp/finegrasp_sunet14_g1b-realsense_10e --list <slot>

    The summary table:

    • Composes: the options the config check accepts under FineGrasp, the one it ships included. needs consent: an option it holds back until you accept the code it downloads (the row says how), neither accepted nor refused. no record: never composed; the row says why.
    • Refused: the options the config check refuses under FineGrasp; each row gives the first sentence of the reason. For losses, both columns count the terms (or sets of terms) a preset was tried on.
    • Runs here: the swaps whose probe trained on real frames under FineGrasp without an error, out of every option tried there as a swap: a refusal counts, the option the method ships does not, and a loss preset is one option. Does it run? counts the same way.

    The lists of each slot:

    • Runs: the methods under which the swap trained on real frames without an error, out of every method it is a swap under; the methods that ship the option are own and not counted. Who is left out, and why, stands under the chip, or below the table when it is long. Measured: 20 training iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, one run per cell; nothing was measured on GraspClutter6D or on Kinect frames.
    • Trains like shipped: trained 250 iterations beside the component the method ships, its losses fall as theirs do, out of the methods it was compared under; a method under which the swap did not run, or where it trained on a schedule of its own, is named and not counted. Level 2 needs runs, not learns: a term flat after 20 iterations can fall by 250. Measured: 250 iterations on 8 RealSense frames of GraspNet-1Billion (one scene), seed 0, at a constant learning rate (FineGrasp: its own warm-up), beside the method as shipped trained the same way twice.
    • Under FineGrasp: ✓ when it reached every level here; level ? (as shipped) when FineGrasp as shipped does not reach that level either (a note below the table says why), so the level says nothing about the option; else the level it missed and why (composes, runs, learns, predicts), or why it was refused.

    The levels, the refusal kinds and the thresholds: How we measure; every record: Does it run?; every comparison at level 2: Does it train like the shipped component?.

    How this port differs from the reference
    • No model class of its own; one model instance trains and predicts.
    • The normal images and the instance-normalised graspness files of the authors' training set are not published. Both are generated here from the paper's equations; the normals are checked through the AP of the released weights, the graspness labels cannot be checked against the authors' at all.
    • The published recipe uses eight processes with four frames each; the runnable config uses one process with 32, which keeps the learning rate and the number of steps but gives batch norm 32 frames instead of 4. With fewer frames per step, scale the rate and the two step counts of the scheduler. None of this has been run beyond a smoke test.
    • A frame with fewer graspable candidates than seeds yields fewer grasps instead of repeats, and a frame with none yields an empty result (as for EconomicGrasp).
    • The released inference processor also drops grasps as wide as the gripper, applies grasp NMS and sorts by score: deployment post-processing, not part of the benchmark metric nor of these configs (GraspNMS exists as a post-processor).

    How it was checked, stage by stage: tests/integration/test_finegrasp_parity.py and the README.
